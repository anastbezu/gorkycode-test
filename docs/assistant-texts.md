# Тексты ассистента

Как ассистент отвечает: подтверждает, переспрашивает, перечисляет, сообщает о находках, отказах и ошибках. По этому документу исполнители агента пишут и проверяют шаблоны ответов, по нему принимаются ответы на демо. Документ ведёт Маша: изменение текстов — PR в этот файл; расхождение, которое нельзя сделать без правки контракта, — к техлиду.

Опирается на [`decisions.md`](decisions.md), [`features.md`](features.md), [`test-cases.md`](test-cases.md), контракты [`contracts/api.md`](contracts/api.md), [`contracts/agent-tools.md`](contracts/agent-tools.md), [`contracts/data-model.md`](contracts/data-model.md) и [`modules/agent.md`](modules/agent.md). Код шаблонов: [`replies.py`](../backend/agent/replies.py), [`list_replies.py`](../backend/agent/list_replies.py), [`search_replies.py`](../backend/agent/search_replies.py).

**Как читать примеры.** Номера — из [`test-cases.md`](test-cases.md); «условно» — примера нет в тест-кейсах. «Сейчас» — как там: среда, 21.10.2026, 10:00. Записи — из стартового набора; их названия цитируются как записаны, в том числе с искажёнными падежами («Подготовить вопросы для Максимом», [`test-cases.md`](test-cases.md), раздел 10). Фигурные скобки `{…}` — подстановка из полей записи.

## 1. Как устроен ответ

Это условия, в которых пишутся все тексты ниже; они не обсуждаются в этом документе.

1. **Один текст для чата и голоса.** У ответа одно поле `reply`; интерфейс показывает его в чате и озвучивает без изменений. Поэтому у каждого ответа **одна** версия, и она должна хорошо звучать вслух. Источник: [`contracts/api.md`](contracts/api.md), «Правила»; [`decisions.md`](decisions.md), «Текст ответа и номера».
2. **Списки и находки рисует интерфейс.** Записи списка, поиска и выбора — пронумерованный список на экране, по строке на запись, без свёртки одинаковых. Номер на экране тот, что пользователь называет («перенеси вторую»). Текст ответа полный список не повторяет: говорит итог и называет не больше трёх ближайших, дальше «Остальные на экране». Свернуть повторы можно только в тексте. Источник: [`contracts/api.md`](contracts/api.md), «Правила»; [`contracts/data-model.md`](contracts/data-model.md), «Правила состояния»; [`modules/agent.md`](modules/agent.md), «Шаблоны ответа».
3. **Текст пишет шаблон в коде, не модель.** Один вызов LLM на реплику, второго хода нет. Модель пишет только текст уточняющего вопроса `AskUser.question`; для него в документе правила (раздел 6), а не промпт. Источник: [`decisions.md`](decisions.md), «Агент»; [`contracts/agent-tools.md`](contracts/agent-tools.md).
4. **Что знает шаблон.** Поля записи (тип, название, начало, конец, «весь день», срок, статус), количество найденного, границы периода как даты (`date_from`, `date_to`). **Чего не знает:** какими словами пользователь назвал период, и не может согласовать слово с родом названия. Поэтому в шаблонах нет «был/была/стоит» при названии записи, а название всегда стоит в кавычках или в начальной форме после двоеточия.
5. **«Да» понимается только в трёх случаях:** ассистент уточняет недостающее при создании, ждёт выбора из нескольких записей или подтверждения отмены нескольких. Вопросы в других ответах («Поискать шире?», «Перенести?») запрещены: пользователь их услышит, а ответ не будет понят. Источник: [`contracts/agent-tools.md`](contracts/agent-tools.md), «Цель изменения»; [`contracts/data-model.md`](contracts/data-model.md), поле `awaiting`.
6. **В ответе одно ожидание:** не больше одного вопроса — одно `awaiting` на реплику. Источник: [`contracts/data-model.md`](contracts/data-model.md).

## 2. Тон и обращение

| Правило | Как выглядит |
|---|---|
| Спокойный, дружелюбный, деловой | «Добавил задачу…», без восторгов |
| **Род: мужской**, прошедшее время | «Добавил», «Перенёс», «Отметил», «Отменил», «Вернул», «Нашёл»: так уже в коде |
| **Обращение на «вы»** в повелительном наклонении, без слова «вы» | «Скажите», «Назовите», «Попробуйте». Там, где можно, без обращения: «Напомню завтра…» |
| Сначала результат, потом детали | «Добавил… завтра, 22 октября, в 15:00» |
| Без вступлений | нет «Конечно!», «С удовольствием!», «Отличный вопрос!» |
| Без повтора фразы пользователя | называем суть: название и когда |
| Без эмодзи, markdown и значков списка | TTS читает их вслух или спотыкается |
| Извиняться не нужно | ошибка называется прямо, с указанием, что сохранено |
| Не оценивать дела пользователя | не «Важная встреча!» |

Названия записей: в кавычках-«ёлочках» и как записаны — после слов «Добавил задачу», «Добавил напоминание», «Отменил», «Перенёс», «Вернул»; с маленькой буквы — после двоеточия и в строках списка («Добавил в календарь: встреча с командой», «Напомню завтра…: позвонить Ивану»), как в [`list_replies.py`](../backend/agent/list_replies.py) `spoken_title`.

## 3. Длина

Ответ один и короткий. Подробности — в списке и карточках на экране ([`contracts/api.md`](contracts/api.md)).

| Вид ответа | Предел |
|---|---|
| Подтверждение одной записи | до 20 слов |
| Подтверждение с предупреждением (пересечение, дубль, «верни» после отмены) | до 35 слов |
| Подтверждение нескольких записей (до 3) | до 45 слов |
| Уточняющий вопрос | до 12 слов, один вопрос |
| Выбор из нескольких | до 20 слов |
| Список и поиск | до 45 слов: итог и **не больше 3** записей, дальше «Остальные на экране» |
| Подтверждение отмены нескольких | до 45 слов |
| Ошибка | до 25 слов |
| Справка и «не по теме» | до 35 слов, 2–3 примера фраз |

## 4. Даты, время и числа в ответе

Правила дат словами сохранены из [`list_replies.py`](../backend/agent/list_replies.py) (`day_words`), добавлены формы «на…» и «до…».

**День словами**
- Ближайшие дни называются словами: «вчера», «сегодня», «завтра», «послезавтра» (23.10 при «сейчас» 21.10 — «послезавтра», а не «пятница»).
- От 3 до 6 дней вперёд — день недели: «в субботу», «в воскресенье», «в понедельник», «во вторник».
- Дальше — дата: «28 октября». Другой год — с годом: «13 сентября 2027 года».
- Дат вида `22.10` и `22.10.2026` в ответах нет: TTS читает их как дробь.

**Три формы дня**

| Где | Форма | Примеры |
|---|---|---|
| Событие, напоминание, список, поиск («в…») | {день} | завтра · в субботу · 28 октября |
| Задача на день («на…») | на {день} | на завтра · на субботу · на 31 октября |
| Срок («до…») | до {день} | до завтра · до воскресенья · до 1 ноября |

**{когда} в подтверждениях** — день словами, затем число месяца (кроме «сегодня»), затем время: «сегодня в 12:00», «завтра, 22 октября, в 15:00», «в субботу, 24 октября, в 11:00», «28 октября, в 13:15». Запятая перед «в» ставится после числа. В списках и поиске число месяца при слове не повторяется: «завтра в 15:00», «в субботу в 10:45».

**Время** — 24-часовое, «в 15:00», «в 09:15». Запись «на весь день» и задача только со сроком — без времени, без «00:00». Окончание называется, только если оно есть в записи: «с 17:00 до 18:30»; встреча без названного окончания окончания не получает ([`contracts/agent-tools.md`](contracts/agent-tools.md), `CreateRecord.end`).

**Числа** — цифрами, как в коде: «2 дела», «8 дел». Как синтез речи читает цифры и время, не проверено — см. раздел 15.

**Названия периодов** шаблон получает как даты (`date_from`, `date_to`). Слов, которыми пользователь назвал период («до конца недели» или «на этой неделе»), он не знает. Стандартные периоды он узнаёт по датам:

| Даты периода | Называется |
|---|---|
| один день | «На сегодня», «На завтра», «На 31 декабря»; прошедший день — «Вчера —», «20 октября —» |
| понедельник–воскресенье текущей недели | «На этой неделе» (прошедшие дни входят) |
| понедельник–воскресенье следующей недели | «На следующей неделе» |
| понедельник–воскресенье прошлой недели | «На прошлой неделе» |
| суббота–воскресенье ближайших выходных | «На выходных» |
| от сегодняшнего дня до даты | «До 25 октября» |
| без конца (`date_to` пуст) | «Начиная с 21 октября» |
| любой другой | «С 26 октября по 1 ноября» |
| граница не в полночь | добавляется время: «На сегодня с 18:00» |

Источник: «эта неделя» — с понедельника по воскресенье, прошедшие дни входят — [`contracts/agent-tools.md`](contracts/agent-tools.md), «Правила»; [`test-cases.md`](test-cases.md) 1.11 (8 записей).

## 5. Создание записей

Умолчания времени и правила дат — [`contracts/agent-tools.md`](contracts/agent-tools.md), «Правила»; [`decisions.md`](decisions.md), «Поведение в разговоре». «В три», «в пять» без уточнения — 15:00 и 17:00, без вопроса; время всегда видно в подтверждении, чтобы ошибку заметили.

Назван только день — задача и напоминание сохраняются «на весь день» без вопроса; дата не названа — сохраняются без даты, без вопроса, ответ говорит «без даты». Время спрашивается только у встречи. Источник: [`contracts/agent-tools.md`](contracts/agent-tools.md), «Правила» (последний пункт о датах); [`features.md`](features.md), «Создание задачи или напоминания»; [`test-cases.md`](test-cases.md) 2.12а, 3.5, 6.4, 1.15.

### 5.1. Задачи

| Случай | Шаблон | Пример |
|---|---|---|
| На день (весь день) | Добавил задачу «{название}» на {день с числом}. | 1.2: Добавил задачу «Отправить отчёт» на послезавтра, 23 октября. |
| На день и время | Добавил задачу «{название}» на {день с числом}, в {время}. | условно: Добавил задачу «Созвониться с банком» на завтра, 22 октября, в 15:30. |
| Со сроком | Добавил задачу «{название}» со сроком до {день с числом}. | 1.3: Добавил задачу «Купить билеты» со сроком до воскресенья, 25 октября. |
| Без даты | Добавил задачу «{название}» без даты. | 2.6: Добавил задачу «Собрать обратную связь по новому продукту» без даты. |

«На следующей неделе» без дня — это срок: воскресенье следующей недели, без начала; ответ как у задачи со сроком ([`contracts/agent-tools.md`](contracts/agent-tools.md), `CreateRecord.deadline`; [`test-cases.md`](test-cases.md) 2.12б): «Добавил задачу «Подготовить акт» со сроком до 1 ноября.»

## 6. Вопросы

### 6.1. Правила

1. **Один вопрос, один «?».** Не больше (факт 6, раздел 1).
2. **Вопрос только в трёх случаях** (факт 5): недостающее при создании (`awaiting = answer`), выбор из записей (`choice`), подтверждение отмены нескольких. Всё остальное — утверждение или просьба без вопроса: «Назовите другое время.», «Попробуйте другие слова.». Предложение «верни» после отмены — не вопрос, а подсказка.
3. **До 12 слов**, без извинений и объяснений, зачем это нужно.
4. **Спрашивается только то, без чего запись не имеет смысла:** время встречи, день встречи, суть напоминания. Не спрашивается: дата у задачи, время у задачи и напоминания (на весь день), длительность, участники, место, «в три» (15:00). Источник: [`features.md`](features.md), «Уточнение недостающих данных»; [`contracts/agent-tools.md`](contracts/agent-tools.md), «Правила».
5. **Ответ дополняет черновик:** «в 14», «завтра» — не новая фраза и не новая запись ([`test-cases.md`](test-cases.md), раздел 3).
6. **Кто пишет вопрос.** Если не хватает времени встречи — вопрос из шаблона в коде ([`replies.py`](../backend/agent/replies.py)). Если не хватает названия или типа при создании — вопрос пишет модель (`AskUser.question`) по правилам 1–4. Если реплику не к чему привязать (нет черновика и фокуса), это не уточнение при создании и не выбор: ответ без вопроса, пользователь называет запись заново.

### 6.2. Тексты вопросов

| Случай | Кто пишет | Шаблон | Пример |
|---|---|---|---|
| Нет времени у встречи (день назван) | код | На какое время поставить встречу? | 1.15: На какое время поставить встречу? |
| Нет ни дня, ни времени у встречи | код | На какой день и во сколько поставить встречу? | 3.1: На какой день и во сколько поставить встречу? |
| Нет дня у встречи, время названо | модель | На какой день поставить встречу? | 3.8: На какой день поставить встречу? |
| Нет сути у напоминания | модель | О чём напомнить? | 3.5: О чём напомнить? |
| Нет сути и времени у встречи | модель | С кем или о чём встреча, и когда? | 3.4: С кем или о чём встреча, и когда? |
| Ответ не к чему привязать (черновик уже сброшен). **Не вопрос**: ответ «да» здесь не понимается, пользователь называет запись заново | код | Не понял, к чему относится {это}. Назовите запись целиком. | 3.15: Не понял, к чему относится это время. Назовите запись целиком. |
| Нет записи, к которой относится «это» (фокуса нет, показано не несколько). **Не вопрос**, по той же причине | код | Не понял, какую запись отметить. Назовите её. | 7.9: Не понял, какую запись отметить. Назовите её. |
| Не хватает другого поля | код, запасной | Не хватает деталей. Что и когда записать? | условно: Не хватает деталей. Что и когда записать? |

### 6.3. Посторонняя реплика посреди уточнения

Посторонняя реплика выполняется, черновик ждёт ещё один ход, к ответу добавляется напоминание о нём. Ещё одна посторонняя реплика его сбрасывает, напоминания нет. Источник: [`contracts/data-model.md`](contracts/data-model.md), «Правила состояния»; [`test-cases.md`](test-cases.md) 3.13–3.15.

| Случай | Шаблон | Пример |
|---|---|---|
| Напоминание о черновике (у черновика есть день) | {ответ на реплику} Запись «{название}» так и не создана — на какое время? | 3.13: На завтра одно дело: 09:15 — подготовить вопросы для Максимом. Запись «Встреча с Иваном» так и не создана — на какое время? |

## 8. Списки

### 8.1. Правила

- Ответ — итог и не больше трёх записей по времени, как на экране; дальше «Остальные на экране» (`MAX_SPOKEN = 3`; [`modules/agent.md`](modules/agent.md), «Шаблоны ответа»).
- Период называется по датам (раздел 4).
- **Слово для итога зависит от типа в запросе** (`ListRecords.types`): один тип — «встреча/встречи/встреч», «задача/задачи/задач», «напоминание/напоминания/напоминаний»; все типы, а также «задачи и напоминания» вместе — «дело/дела/дел» («одно дело», «2 дела», «5 дел»).
- Пустой период: «На {период} ничего не запланировано.» Если запрошен один тип — «На {период} встреч нет.» / «напоминаний нет.» / «задач нет.»
- «Сегодня» показывает весь день: строки «Уже прошло» нет, прошедшие записи называются как все. Полный список на экране в любом случае ([`test-cases.md`](test-cases.md) 1.6 — обе записи).
- Запись «на весь день» и задача только со сроком называются без времени; запись без даты — «(без срока)».
- Для периода из нескольких дней записи названы с днём: «сегодня в 08:00 — …», «29 октября, в 15:30 — …». Для одного дня — без дня: «08:00 — …».
- Если в списке больше трёх записей, перед ними стоит «Первые по времени:» (в периоде могут быть и прошедшие записи, слово «ближайшие» тогда неверно).

## 9. Поиск

### 9.1. Правила

- Называется **одна** запись: «Ближайшая» (есть записи, которые ещё впереди — ближайшая будущая) или «Последняя» (все в прошлом). Выбор — по датам записей, не по порядку выдачи ([`search_replies.py`](../backend/agent/search_replies.py)).
- Направление во времени («когда **была**») задаёт модель фильтром дат запроса (`SearchFilters.date_to`), а не текст. Пример 1.13 и 5.3 предполагают, что для «была» модель ставит `date_to` = сейчас; без фильтра ответ назовёт и будущие записи.
- **Слово для итога** — по типу найденных записей: все встречи — «Нашёл 3 встречи», все задачи — «Нашёл 7 задач», разные типы — «Нашёл 8 записей».
- **Повторы** — записи с одинаковым названием (без учёта регистра и пробелов). Если все найденные записи одного названия, ответ называет название и число повторов: ««{название}» — {N} раз» (раз/раза/раз). Повторы сворачиваются только в тексте: на экране и в номерах они отдельные строки. Источник: [`test-cases.md`](test-cases.md) 5.3, [`contracts/api.md`](contracts/api.md), «Правила».
- **Ограничение.** Названия, которые различаются хвостом («Созвон с Севером по CRM», «… по интеграции»), шаблон не объединяет: он не умеет выделять общую часть. В 5.3 ответ — «Нашёл 7 встреч. Последняя — …»; формулировка «созвон с Севером — 7 раз» достижима, только если названия записей совпадают целиком.
- **Ничего не найдено — без вопроса.** «Поискать шире?» запрещено (факт 5): ответ «да» не будет понят. Вместо вопроса — просьба: «Попробуйте другие слова.»
- Одна запись называется без «была» и «стоит»: ««Название» — 22 августа, в 20:30.» (факт 4). Запись без времени — только день.

### 9.2. Шаблоны

| Случай | Шаблон | Пример |
|---|---|---|
| Ничего не найдено | По запросу «{запрос}» ничего не нашлось. Попробуйте другие слова. | 5.16: По запросу «аквапарк» ничего не нашлось. Попробуйте другие слова. |

## 11. Ошибки

Тексты ошибок модели — [`modules/agent.md`](modules/agent.md), «Ошибки»: пользователь получает `ChatResponse` с понятным `reply` и `result = None`. **Правило: каждая ошибка прямо говорит, что сохранено** — пользователь не должен гадать, появилась ли запись.

### 11.1. Ответы ассистента (`reply`)

| Случай | Шаблон | Пример |
|---|---|---|
| Нет ключа или модели (`LLMConfigError`) | Ассистент не настроен: задайте ключ и модель в настройках. Ничего не сохранено. | условно: Ассистент не настроен: задайте ключ и модель в настройках. Ничего не сохранено. |
| Модель недоступна (`APIError`: таймаут, сеть, лимит, 5xx) | Сервис, который понимает запросы, сейчас недоступен. Ничего не сохранено, попробуйте ещё раз. | условно: Сервис, который понимает запросы, сейчас недоступен. Ничего не сохранено, попробуйте ещё раз. |
| Запрос не разобран (`ActionParseError`) | Не понял запрос, ничего не сохранено. Скажите иначе, например: «Напомни завтра в 10 позвонить Ивану». | условно: Не понял запрос, ничего не сохранено. Скажите иначе, например: «Напомни завтра в 10 позвонить Ивану». |
| Сбой сохранения | Не удалось сохранить. Загляните в «Мои дела»: если записи нет, повторите запрос. | условно: Не удалось сохранить. Загляните в «Мои дела»: если записи нет, повторите запрос. |

Про сбой сохранения: пока `create_record` и сохранение состояния коммитят отдельно, запись могла создаться, а состояние нет ([`modules/agent.md`](modules/agent.md), «Ограничения этой версии»). Поэтому в тексте нет «ничего не сохранено» — он просит проверить «Мои дела». Когда останется один коммит на реплику, можно заменить на «Не удалось сохранить, ничего не создано».

В тексте не «сервис распознавания» (так названа ошибка модели в [`modules/agent.md`](modules/agent.md)): «распознавание» пользователь связывает с голосом, а не с моделью.

## 13. Правила, которые проверяет код

Исполнители агента проверяют шаблоны тестами по этому списку. Примеры этого документа проверены теми же правилами скриптом.

| № | Правило | Как проверить |
|---|---|---|
| 1 | Нет `ДД.ММ` и `ДД.ММ.ГГГГ` (кроме времени `ЧЧ:ММ`) | регулярное выражение |
| 2 | Нет эмодзи | диапазоны Unicode |
| 3 | Нет markdown и значков списка: `*`, `#`, `_`, обратных кавычек, «- » и «1)» в начале | регулярное выражение |
| 4 | Нет вступлений: «Конечно», «С удовольствием», «Разумеется», «Отличный вопрос» | начало ответа |
| 5 | Не больше одного знака «?» | подсчёт |
| 6 | «?» есть, только если `awaiting` не пусто, и тогда ровно один | сравнение с `awaiting` |
| 7 | Подтверждение одной записи — до 20 слов; с предупреждением — до 35; нескольких — до 45 | подсчёт слов (тире не слово) |
| 8 | Вопрос — до 12 слов (без напоминания о черновике и без подтверждения отмены) | подсчёт слов |
| 9 | Список и поиск — до 45 слов; в тексте названо не больше 3 записей | подсчёт слов и записей |
| 10 | Ошибка — до 25 слов | подсчёт слов |
| 11 | В ошибке сказано, что сохранено: «ничего не сохранено», «не создана» или «не удалось сохранить» | поиск фразы |
| 12 | Подтверждение создания содержит название записи и, если дата названа, день словами и время (кроме «весь день») | поиск названия, дня, `ЧЧ:ММ` |
| 13 | Подтверждение создания встречи без `end` не содержит окончания; с `end` — «с … до …» | сравнение с записью |
| 14 | В ответе нет UUID | регулярное выражение |
| 15 | Название записи — как в записи (допустимо: первая буква строчная после двоеточия) | сравнение с `title` |
| 16 | Ответ не содержит «Озвучка», «Текст:» — версия одна | поиск |
| 17 | При пустом результате списка и поиска нет вопроса | «?» отсутствует |
| 18 | Слово типа («встреча/задача/напоминание», «дело») согласовано с числом (1, 2–4, 5+, 11–14) | функция склонения |

## 14. Что делать с текущими шаблонами в коде

Решение по каждому пункту: оставить или изменить, и важно ли это для демо ([`test-cases.md`](test-cases.md), раздел 11: шаги 1–6). Знак ★ — критично для демо.

| № | Сейчас в коде | Решение | Для демо |
|---|---|---|---|
| 1 | Период из нескольких дней называется датами: «С 26 октября по 1 ноября — 4 дела» | **Изменить.** Стандартные периоды (эта, следующая, прошлая неделя, выходные) узнавать по датам и называть словами; период от сегодняшнего дня — «До 25 октября»; остальное датами (раздел 4). Слова, которыми пользователь назвал период, шаблон не знает (факт 4), но даты у него есть | нет |
| 2 | Всегда «дела»: на «Какие встречи на неделе?» — «2 дела» | **Изменить.** Тип известен из `ListRecords.types`: один тип — «встречи», «задачи», «напоминания»; все типы или «задачи и напоминания» — «дела» (раздел 8) | нет (шаг 4 — все типы, там «дела» верно) |

## 15. Открытое

- **Чтение чисел и времени вслух.** Озвучка — `speechSynthesis` браузера ([`decisions.md`](decisions.md), «Синтез речи»; [`contracts/api.md`](contracts/api.md)). Как он читает «2 дела», «09:15», «22 октября» в Chrome, Safari (iOS), Android, не проверено. До проверки цифры оставлены как в коде (раздел 4). Проверить 5–10 ответов на целевых устройствах до демо; если звучит плохо — заменить числа до десяти словами и менять время на «в девять пятнадцать».
