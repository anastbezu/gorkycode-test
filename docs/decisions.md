# Технические решения

Выбранные технологии и коротко — почему. Заполняется по мере принятия решений.

| Область | Решение | Почему |
|---|---|---|
| Язык и фреймворк | Python 3.13, FastAPI, Pydantic v2; слои `api / agent / services / db` | Pydantic-модели — одновременно контракт, валидация и документация API; асинхронные вызовы LLM |
| Доступ к БД | SQLAlchemy 2, Alembic, psycopg 3; сервисы и поиск синхронные, сессию БД получают первым аргументом от вызывающего, асинхронный код (агент) вызывает их через `asyncio.to_thread`; сервисы не коммитят — один коммит на реплику в маршруте `POST /api/chat` | стандартный стек для FastAPI, миграции схемы; синхронный код проще, а вызов в потоке не блокирует сервер для других пользователей; запись и состояние разговора сохраняются вместе — «верни» всегда может откатить изменение |
| База данных | PostgreSQL + pgvector | записи, векторы и полнотекстовый поиск в одной базе |
| Поиск по старым записям | модуль поиска, два уровня: «точно» — все значимые слова запроса в названии (основа слова или почти совпадающее слово), если пусто — «похожие» по смыслу (локальная модель `rubert-mini-frida`, pgvector); фильтры SQL до поиска; вектор — на текст, считает модуль поиска | честно отвечает «не нашёл» и находит записи с искажёнными падежами; модель на сервере — без ключа, сети и лимитов |
| Цель изменения («перенеси встречу с Иваном») | модуль поиска, `find_target()`: только точное совпадение слов + названное время; похожие — только вопросом | ошибка безопасна: «не нашёл» вместо изменения чужой записи |
| Агент | один вызов LLM на реплику: LLM выбирает действие и аргументы, код исполняет; состояние разговора хранит сервер | предсказуемо, меньше запросов к LLM |
| Проверка агента | pytest по эталонным кейсам `docs/test-cases.md`: в CI без модели, живой прогон через модель — руками перед мержем изменений промпта, инструментов и схем действий | ловит, когда правка одного ломает сценарии другого; ключ не лежит в публичном CI |
| Контекст разговора | в промпт — короткий текст состояния: показанные записи под номерами, последнее действие, черновик; модель ссылается номером или фокусом, id подставляет код | «вторую», «её», «нет, в 16», «не эту, а ту» работают без истории сообщений и без лишнего вызова LLM |
| Поведение в разговоре | умолчания времени («в 3» = 15:00, «вечером» = 18:00), отмена сразу с откатом «верни», конфликт — сохранить и предупредить, отказ «не надо» ловит код | меньше ходов и вызовов LLM; ответ всегда называет дату, ошибку ловит поправка |
| Текст ответа и номера | один текст ответа для чата и голоса, озвучивается как есть; найденные записи интерфейс показывает пронумерованным списком, «вторую» — номер на экране | один шаблон на ответ, чат и голос не расходятся; пользователь называет номер, который видит |
| Даты и время | LLM выдаёт дату в ISO 8601 с часовым поясом, код проверяет; время не названо — «весь день» или уточняющий вопрос | без лишних зависимостей, без «тихой полуночи» |
| Пользователи | вход по желанию: гость (свои записи у браузера) или учётка по логину и паролю, токен в `Authorization` | страница работает сразу, без формы; учётка — те же данные на любом устройстве |
| LLM | OpenAI SDK, совместимый API, tool calling; по умолчанию Gemini, свой ключ в настройках браузера | не привязываемся к одному провайдеру, проверяющий может подставить свой ключ |
| Датасет | копия 1000 записей только демо-учёткам (жюри и команда), сбрасывается к исходной; гость и новые учётки пустые; типы из текста | поиск и списки показываются на демо-учётке, «создать» начинается с чистого календаря, база не растёт от каждого визита |
| Управление записями из интерфейса | кнопки создают, переносят, отмечают выполненной, удаляют и возвращают через REST `/api/items` теми же сервисами, что агент; удаление мягкое | без вызова LLM и промахов; кнопка и голос ведут себя одинаково, ошибочный клик исправляется «Вернуть» |
| Распознавание речи (STT) | на сервере: `POST /api/stt` (аудио → текст), затем обычный `/api/chat`; сначала Gemini на серверном ключе, запись до 30 секунд | распознавание в браузере работает не во всех браузерах, а голос — главный сценарий; контракт чата не меняется; пользователь видит распознанный текст |
| Синтез речи (TTS) | голос браузера (`speechSynthesis`) озвучивает `reply` | без второго внешнего вызова и аудио в ответе; ответ и так короткий и «на слух» |
| Интерфейс | веб-интерфейс (чат + боковая панель «Мои дела»), стек на усмотрение фронтендера | совмещение свободного диалога и структурированного списка задач |
| Хостинг | свой VPS, Docker Compose, Nginx + Let's Encrypt (certbot) | HTTPS обязателен для доступа к микрофону |
