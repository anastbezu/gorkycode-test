# Контракт: поиск

Граница: поиск (Родион) ↔ агент (Илья, Давид). Типы — `data-model.md`, `SearchFilters` — `agent-tools.md`.

Модуль поиска отвечает за всё, что связано с поиском записей: вопрос пользователя («когда был созвон с юристами?») — `search()`, и поиск записи, которую нужно изменить («перенеси встречу с дизайнером»), — `find_target()`. Агент вызывает эти две функции и не ищет записи сам.

```python
from typing import Literal
from uuid import UUID
from pydantic import AwareDatetime, BaseModel
from sqlalchemy.orm import Session

class SearchHit(BaseModel):
    record: Record
    score: float
    match: Literal["exact", "similar"] = "exact"   # «точно» или «похоже по смыслу»

def search(db: Session, user_id: UUID, query: str, filters: SearchFilters,
           limit: int = 10) -> list[SearchHit]: ...

class TargetMatch(BaseModel):
    exact: list[Record] = []     # подходят точно — по ним можно действовать
    similar: list[Record] = []   # похожи по смыслу — только предложить вопросом

def find_target(db: Session, user_id: UUID, text: str | None, when: AwareDatetime | None,
                filters: SearchFilters | None, statuses: list[RecordStatus],
                limit: int = 21) -> TargetMatch: ...
```

## Общие правила
- Синхронные, как сервисы записей: сессию БД передаёт вызывающий первым аргументом, транзакцией управляет он. Агент вызывает их через `asyncio.to_thread` (`docs/decisions.md`, «Доступ к БД»).
- Фильтры (пользователь, тип, даты, статус) применяются до сравнения текста.
- **«Точно»** — в названии записи есть каждое значимое слово запроса: по основе слова («юристами» ↔ «юристом») или почти совпадающее слово (опечатка, искажённый падеж). Значимые — без служебных слов («с», «про», «по») и без слов типа записи («задачу», «напоминание», «встречу»), если в названии их нет.
- **«Похоже»** — близко по смыслу (векторы), выше порога похожести; ниже порога записи не возвращаются.
- Одинаковые тексты с разными датами — разные записи.
- Векторы считает модуль поиска сам; сервисы записей при создании и изменении записи поиск не вызывают. Модель одна на сервере, от `llm_config` пользователя не зависит.

## `search()` — вопрос пользователя
- Сначала уровень «точно». Нашлось — возвращаются только точные, `match="exact"`.
- Не нашлось точно — похожие выше порога, `match="similar"`; ответ говорит «точно не нашёл, похожие: …».
- Ни того, ни другого — пустой список: «ничего не нашлось».
- Уровни не смешиваются: в одном ответе все `exact` или все `similar`.
- Интервал дат необязателен: «когда-то ставил задачу» — без дат.
- Результатов не больше `limit`. Порядок — по дате записи, от новых к старым, записи без даты — в конце; этот порядок — номера на экране.

## `find_target()` — какую запись менять
Вызывается для `TargetRef` с `text` и/или `when` (`agent-tools.md`, «Цель изменения»); `index` и `focus` агент разрешает сам, без поиска.
- `statuses` — среди каких записей искать: `[active]` для изменения, выполнения и отмены; `[done, cancelled]` для «верни в активные», «не выполнено».
- `text` → уровень «точно»; похожие по смыслу в `exact` не попадают никогда.
- `when` сужает точные: сначала запись с тем же днём и временем, затем — тот же день, затем — то же время в другой день. Под `when` не подошла ни одна — `exact` пуст, а точные по словам уходят в `similar`.
- `text = None` (например, «отмени всё на завтра») — все записи по `filters` и `when`, в `exact`.
- `similar` заполняется, только если `exact` пуст: до 3 записей, близких по смыслу, — чтобы спросить «Может, эту?». Исполнять их без ответа пользователя нельзя.
- Порядок в `exact` и `similar` — по началу записи, от ранних к поздним, без даты — в конце; этот порядок — номера на экране. Больше `limit` не возвращается: `limit` = 21 позволяет агенту понять «больше 20 — слишком много».
