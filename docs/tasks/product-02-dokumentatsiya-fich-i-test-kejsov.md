# product-02: документация фич и эталонные тест-кейсы

**Исполнитель:** Маша

## Цель
Актуализировать и перенести продуктовые спецификации из твоих рабочих черновиков (список фич P0–P3, который ты присылала в чат команды, и твой файл тестовых фраз) в репозиторий в виде двух структурированных документов: `docs/features.md` (карта возможностей продукта) и `docs/test-cases.md` (эталонные фразы и сценарии для демонстрации и тестирования), устранив расхождения с утверждёнными техническими решениями.

## Контекст
- **Синхронизация с решениями команды:**
  В репозитории уже утверждены технические решения ([`docs/decisions.md`](../decisions.md)) и контракты ([`docs/contracts/`](../contracts/)). Черновики содержат ряд устаревших предположений, которые необходимо привести в соответствие с фактами:
  1. **Авторизация:** В черновиках авторизация указана как открытый вопрос. В продукте **авторизации нет**: у каждого браузера изолированное персональное хранилище по сессионному идентификатору `X-User-Id` (`docs/decisions.md`). Любые упоминания логинов, паролей и регистрации должны быть исключены.
  2. **Модель данных ([`docs/contracts/data-model.md`](../contracts/data-model.md)):**
     - Типы записей строго: `task` (дело без жёсткого времени), `meeting` (встреча с кем-то), `reminder` (напоминание к моменту).
     - Статусы строго: `active`, `done`, `cancelled`.
  3. **Стартовый датасет:** Новому пользователю при первом открытии автоматически загружается персональная копия 1000 записей реальных событий из датасета, чтобы списки и поиск сразу работали на демонстрации.
- **Требования к файлу `docs/features.md`:**
  - Описать возможности ассистента, сгруппированные по приоритетам:
    - **P0 (Обязательное ядро):** 4 базовых сценария (создание дела со всеми параметрами; создание с уточнением недостающих данных; календарный список дел на день/неделю; поиск старых дел по смыслу через pgvector), голосовой ввод через микрофон, чат-интерфейс с боковой панелью «Мои дела».
    - **P1 (UX и вау-эффект):** интерактивные чипы быстрого выбора в чате (выбор времени в один клик; выбранное значение уходит ассистенту обычной репликой), лаконичные голосовые ответы (без зачитывания простыней текста), просмотр карточек дел.
    - **P2 (Бонусы и расширения):** редактирование/удаление, темная тема, экспорт расписания.
  - Текст должен быть написан понятным языком для жюри и пользователей, описывая ценность каждой фичи.
- **Требования к файлу `docs/test-cases.md`:**
  - Собрать и структурировать эталонные фразы пользователей для ручной проверки и демонстрации ассистента:
    - **Сценарий 1 (Создание):** фразы с точным временем, относительными датами («завтра в 15:00», «в эту пятницу утром», «через два часа»).
    - **Сценарий 2 (Уточнение):** фразы без времени («создай встречу с Иваном»), ожидаемый переспрос ассистента и варианты ответов (голосом или кликом по чипу).
    - **Сценарий 3 (Списки за период):** запросы расписания («что у меня сегодня?», «какие планы на завтра?», «встречи до конца недели»).
    - **Сценарий 4 (Смысловой поиск):** запросы поиска по архиву без точных дат («найди задачу про договор», «когда созвон с юристами?», «что я должен был купить?»).
  - **Сценарий демонстрации (Golden Demo Flow):** пошаговый сценарий из 5–6 шагов для показа проекта менторам и жюри на `https://gorky.bond` (от первого захода и стартовых дел до голосового диалога).

- Контракты данных и инструментов агента: [`docs/contracts/data-model.md`](../contracts/data-model.md), [`docs/contracts/agent-tools.md`](../contracts/agent-tools.md).
- Твои черновики: список фич P0–P3 и файл тестовых фраз (в репозитории их нет — содержимое переносится в `docs/features.md` и `docs/test-cases.md`).

## Критерии готовности
- [ ] В репозитории создан файл `docs/features.md`, полностью очищенный от упоминаний авторизации и согласованный с `docs/decisions.md`.
- [ ] В `docs/features.md` чётко выделены 4 обязательных сценария прототипа и их продуктовая ценность.
- [ ] В репозитории создан файл `docs/test-cases.md`, содержащий не менее 10 эталонных фраз на каждый из 4 ключевых сценариев.
- [ ] В `docs/test-cases.md` описан сквозной пошаговый сценарий «Golden Demo» для проверки перед защитой на живом стенде `https://gorky.bond`.
