# agent-07: изменить, выполнить, отменить, вернуть; несколько команд в одной фразе; справка

**Исполнитель:** Илья. После [agent-05](agent-05-integratsiya-s-servisami-i-api.md).

## Цель
Бонусные сценарии задания — изменение и удаление голосом, отметка «выполнено», обработка неоднозначных запросов — плюс то, что делает разговор естественным:
- «Перенеси встречу с Иваном на пятницу», «Перенеси вторую на пятницу», «Сдвинь её на час позже», «Нет, не в 15, а в 16»;
- «Я позвонил Ольге», «Отметь задачу про отчёт выполненной», «Нет, ещё не позвонил»;
- «Отмени встречу с дизайнером» → «Верни»; «Нет, не этот, а тот, что по сайту»;
- «Отмени все созвоны на этой неделе» → «Отменить 3 созвона: …?» → «Да»;
- «Запиши задачу подготовить акт и поставь встречу с Максимом завтра в 16» — обе команды за одну реплику;
- «Какая погода?», «Что ты умеешь?» — справка, ничего не создаётся.

### Цель изменения: как найти запись
По `TargetRef`, ровно один из способов:
- `index` → запись `shown[index - 1]`; номера нет в `shown` → `ok=False`, ответ «В показанном списке нет записи № N».
- `focus` → `focus_record_id`; фокуса нет → ответ-вопрос «Какую запись?» с последними показанными (если есть).
- `text` (+ `when`) → `search()` по `text` с фильтром `status=[active]` (для «верни в активные» и «не выполнено» — `[done, cancelled]`) и датой из `when`, если она названа; затем упорядочить кандидатов по точности: совпали дата и время → совпало время → совпало название → остальные. Будущие записи — раньше прошедших; прошедшие берутся, только если будущих нет, и ответ называет дату («перенёс встречу 05.03.2026…»).
- Одна подходящая → исполнить. **Несколько** → ничего не менять: `ActionResult(ok=False, candidates=[…])`, в состоянии — `pending` = это действие, `candidates`, `awaiting="choice"`, `shown` = кандидаты в порядке `candidates` — это номера на экране ([`api.md`](../contracts/api.md), «Правила»); если ответ называет варианты с номерами, то в том же порядке: «Встреч с Иваном две: 1) завтра в 15:00; 2) 20.03.2027 в 08:45. Какую перенести?». Следующая реплика («вторую», «ту, что в марте», нажатие чипа) приходит текстом; модель видит «Показано» и возвращает то же действие с `index` — исполнить, очистить кандидатов и черновик.
- Ни одной → `ok=False`, «Не нашёл встречу с Иваном».
- **Несколько записей одной командой** («отмени все созвоны», «отмени всё на завтра», «отметь все задачи про отчёт выполненными») — `set_status` с `target.all = True` и описанием (`text`, `when`, `filters`). Код находит все подходящие активные записи (не больше 20; больше — «Слишком много, уточните»), ничего не меняет и спрашивает подтверждение: «Отменить 5 созвонов: 1) … 5) …?» — `candidates`, `shown`, `pending`, `awaiting="choice"`. Ответ «да», «все» — модель возвращает `set_status(target={all: true})` без описания, код применяет его ко всем записям из `shown` одним ходом. Ответ «вторую» — только к ней. Подошла одна запись — сразу, без подтверждения. `last_action` — все записи и их прежние статусы: «верни» откатывает всё разом. Изменение (`update_record`) нескольких записей одной командой — вне задачи.

### Действия
- **`update_record`**: меняются только переданные поля; «перенеси на пятницу» — модель присылает новый `start` с прежним временем (время она видит в «Показано» или «В фокусе»). Проверки и конфликт — в сервисе Дениса; пересечения — в `conflicts`, ответ предупреждает: «В это же время у вас созвон с Альфой». Прежние значения — в `last_action.before`.
- **`set_status`**: `done`, `cancelled`, `active`. Отмена — **сразу, без подтверждения**: отмена обратима. Ответ называет запись и дату и предлагает вернуть: «Отменил встречу с дизайнером, чт 22.10 11:00. Скажите „верни“, если не то».
- **`undo_last`** («верни», «верни как было»): откат `last_action` — изменение прежними значениями, смена статуса прежним статусом, создание отменой созданной записи. Откаченные записи — в `ActionResult.restored`. После отката `last_action` очищается: второе «верни» отвечает «Нечего возвращать». Нет `last_action` — тот же ответ.
- **`replaces_last=True`** («нет, не этот, а тот, что по сайту»): сначала откат `last_action` (в `restored`), затем то же действие с новой целью (в `records`). Новая цель неоднозначна — откат уже сделан, дальше выбор как выше. Ответ одной фразой: «Вернул созвон с Вектором по интеграции и отменил созвон по сайту 14.12.2027».
- **`help`**: `kind=help` — короткое приветствие и 2–3 примера фраз; `kind=offtopic` — «Я веду задачи, встречи и напоминания. Например: …». Состояние не меняется, ничего не создаётся.
- **Поправка** («нет, не в 15, а в 16» сразу после создания) — это `update_record` с `focus`; отдельной логики не нужно, если agent-06 ставит фокус на созданную запись.

### Несколько команд в одной фразе
- Сначала проверь живым запросом к модели по умолчанию (Gemini через OpenAI-совместимый адрес), возвращает ли она несколько `tool_calls` на фразу с двумя командами при `tool_choice="required"`. Результат (что пришло, с какими параметрами запроса) — в `docs/modules/agent.md`.
- Если возвращает: все `create_record` (не больше трёх) исполняются по очереди, ответ один («Записал задачу „подготовить акт“ и встречу с Максимом завтра в 16:00»), `ActionResult.records` — все созданные; `last_action.record_ids` — все, фокуса нет. Любое другое сочетание (например, создание и отмена) — исполняется первый вызов, ответ добавляет «Остальное скажите отдельно».
- Если не возвращает ни при каких разумных параметрах — оставить «первый вызов + остальное скажите отдельно» и записать это в `docs/modules/agent.md`. Кейс 8.9 допускает оба исхода.

### Повторы в ответах
Одинаковые тексты с разными датами (в стартовом наборе 376 уникальных текстов на 1000 записей) шаблон списка и поиска сворачивает в тексте ответа: «Созвон с Севером — 7 раз, последний 22.08.2026». Сворачивается только `reply` (он же озвучивается). Сервисы и поиск отдают все записи, `ActionResult.records` и `shown` содержат их по отдельности, интерфейс показывает каждую своей пронумерованной строкой — номер «вторую» берётся с экрана, а не из текста ответа ([`api.md`](../contracts/api.md), «Правила»; [`data-model.md`](../contracts/data-model.md), «Правила состояния»).

### Формулировки ответов
`reply` — один текст для чата и голоса, интерфейс озвучивает его как есть ([`api.md`](../contracts/api.md)). Примеры ответов в этой задаче показывают смысл, а не окончательный текст: формулировки, формат дат и длину задаёт Маша в `docs/assistant-texts.md` ([product-03](product-03-teksty-assistenta.md)). Пока документа нет — пиши по смыслу примеров; когда появится — шаблоны приводятся к нему.

## Критерии готовности
- [ ] Модель получает новые инструменты; `execute` исполняет `update_record`, `set_status`, `undo_last`, `help`.
- [ ] Кейсы [`test-cases.md`](../test-cases.md) раздела 7 (7.1–7.22) и 8.1, 8.2, 8.5–8.9 проходят на модели по умолчанию; что не прошло — записано в `docs/modules/agent.md` с причиной.
- [ ] Неоднозначная цель ничего не меняет до выбора; выбор номером следующей репликой исполняет то же действие.
- [ ] «Нет, не этот, а тот» одним ходом возвращает первую запись и меняет вторую; второе «верни» отвечает «Нечего возвращать».
- [ ] Отмена одной записи — без подтверждения, ответ называет запись и предлагает «верни»; нескольких («отмени все созвоны») — после «да», «верни» откатывает все.
- [ ] Результат проверки нескольких `tool_calls` у Gemini записан в `docs/modules/agent.md`; поведение соответствует результату.
- [ ] Смоук-тесты `pytest` без сети (с подменённым `get_action`): разрешение цели по `index`, `focus`, `text`; выбор из кандидатов; откат изменения, статуса и создания; `replaces_last`.
