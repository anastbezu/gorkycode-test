## Цель
Страница, как и раньше, сразу работает без входа. Нажал «Войти», ввёл логин и пароль демо-учётки — и на любом устройстве видишь одни и те же записи. Вышел — снова свои записи гостя.

## Что решено и почему
- Вход **по желанию**: первый экран жюри — работающий ассистент, а не форма.
- Гость и новая учётка начинают **пустыми**; датасет (1000 записей) есть только у демо-учёток. Демо-учётка для жюри — логин и пароль в README; у каждого из команды — своя.
- Записи гостя к учётке **не переходят**: вошёл — данные учётки, вышел — снова данные гостя. Разговор после входа и после выхода начинается заново.
- Токен истёк или недействителен — страница **продолжает гостем** и говорит об этом. Повторно запрос гостем не отправляется: пользователь хотел действовать от учётки.

## Стек — не меняется

Бэкенд не трогать.

## Контракт — что важно клиенту
```ts
// добавить в src/api/types.ts — один в один из api.md
export interface Credentials { login: string; password: string }
export interface Account { id: string; login: string; demo: boolean }
export interface AuthResponse { token: string; account: Account }
```
- `POST /api/auth/register` (тело `Credentials`) → 201 `AuthResponse`; 409 — логин занят.
- `POST /api/auth/login` (тело `Credentials`) → 200 `AuthResponse`; 401 — неверный логин или пароль.
- `POST /api/auth/logout` с токеном → 204, тела нет.
- `GET /api/auth/me` с токеном → 200 `Account`; 401 — токен недействителен.
- Ошибки — `{"detail": "..."}`: 401, 409, 422 (логин 3–32 символа из `A-Z a-z 0-9 _ . -`, пароль от 8), 429 (слишком много попыток). Текст `detail` показывать как есть.
- Вошёл — **каждый** запрос `/api/*` (чат, `/api/items`, `/api/stt`, позже кнопки записей) уходит с заголовком `Authorization: Bearer <token>` и **без** `X-User-Id`. Не вошёл — как сейчас, с `X-User-Id`.

## Что сделать

### 1. Хранение — `src/lib/storage.ts`
- Новый ключ `gorky.auth` — объект `{ token, account }` (`AuthResponse`) или его нет. Функции `loadAuth(): AuthResponse | null` и `saveAuth(auth: AuthResponse | null)` — по образцу `loadUserId` и `saveUserId` (через те же `read` и `write`, ошибки localStorage не роняют страницу).
- `gorky.userId` (гость) **не удалять** при входе: после выхода пользователь возвращается к своим записям гостя.
- Обновить комментарий в начале файла: список ключей.

### 2. Клиент — `src/api/client.ts`
- Модульная переменная `auth`, загружается `loadAuth()` при старте, как `userId`.
- `headersFor` получает ещё и токен: есть `auth` — ставит `Authorization: Bearer <token>` и не ставит `X-User-Id`; нет — как сейчас.
- `asUser`: при входе очередь «первого запроса без id» не нужна — запрос уходит сразу с токеном. `rememberUser` с токеном не вызывается: `X-User-Id` в ответе учётки нет, а гостевой id портить нельзя.
- **401 на запрос, ушедший с токеном** (в `sendChat`, `fetchItems`, `transcribe` — одно общее место, не копировать в каждую функцию): забыть вход (`auth = null`, `saveAuth(null)`), оповестить подписчиков, бросить `ApiError('rejected', 401, 'Сессия входа истекла — вы снова гость. Войдите ещё раз.')` (текст — из макета, если там другой). Запрос гостем **не повторять**. Подписка — `onSessionExpired(listener)` по образцу `onProfileReset`.
- Новые функции, все — через `fetchWithTimeout` и `parse` (таймаут 30 с):
  - `login(c: Credentials): Promise<AuthResponse>` и `register(c: Credentials): Promise<AuthResponse>` — без `Authorization` и без `X-User-Id`; при успехе сохраняют `auth` (переменная и `saveAuth`);
  - `logout(): Promise<void>` — `POST /api/auth/logout` с токеном; **локально вход забывается в любом случае** (и при 204, и при ошибке сети): пользователь нажал «Выйти» — он вышел. Ответ 204 без тела — `parse` не вызывать, он ждёт JSON;
  - `fetchMe(): Promise<Account>` — проверка сохранённого токена;
  - `currentAccount(): Account | null` — кто вошёл сейчас.
- 401 у `login` — это «неверный логин или пароль», а **не** «сессия истекла»: правило выше — только для запросов, ушедших с токеном.

### 3. Тесты — `src/api/client.test.ts`
По образцу существующих (подменённый `fetch`, проверка заголовков):
- без входа запрос уходит с `X-User-Id`, без `Authorization`;
- после `login` все запросы — с `Authorization`, без `X-User-Id`; гостевой id в localStorage остался;
- 401 на запрос с токеном → вход забыт, подписчик вызван, запрос не повторён, ошибка `rejected` 401;
- 401 на `login` → вход не забывается (его и не было), подписчик не вызван, ошибка с `detail` сервера;
- `logout` забывает вход и при 204, и при обрыве сети;
- 409 и 422 у `register` → `ApiError('rejected')` с `detail`.

### 4. Состояние страницы — `src/App.tsx`
- `const [account, setAccount] = useState<Account | null>(currentAccount)`.
- При открытии страницы: если вход сохранён — `fetchMe()`. 200 — обновить `account`; 401 — сработает общий обработчик (п. 2); сеть недоступна — оставить сохранённый вход, страница работает как обычно.
- `onSessionExpired` → `setAccount(null)`, начать разговор заново (п. «Смена пользователя»), баннер с текстом об истёкшем входе (через существующий `setBanner`).
- **Смена пользователя** (вход, регистрация, выход, истёкший вход) — одна функция, например `switchUser(next: Account | null)`:
  - `setAccount(next)`;
  - лента пустая: `setChat({ conversationId: null, messages: [] })` — старый `conversation_id` у другого пользователя всё равно дал бы 404;
  - остановить озвучку (`stopSpeaking`) и запись голоса, если идёт;
  - перезапросить «Мои дела» (`panel.load()`);
  - календарь перечитать: проще всего `<CalendarView key={account?.id ?? 'guest'} … />` — новый ключ пересоздаёт компонент и он загрузит записи заново.

### 5. Интерфейс — по макету
- **Новый компонент `src/components/AuthModal.tsx`** — модальное окно, разметка и закрытие как у `SettingsModal` (`modal`, `modal__dialog`, клик по фону и крестик закрывают). Два режима: «Вход» и «Регистрация», переключаются внутри окна. Поля «Логин» и «Пароль» (`type="password"`, `autoComplete="username"` / `"current-password"` или `"new-password"`). Кнопка отправки неактивна, пока идёт запрос; Enter отправляет. Ошибка — текстом под формой (`detail` сервера). Успех — закрыть окно и вызвать `switchUser(account)`.
- Подсказки по правилам логина и пароля можно показывать до отправки, но решает сервер: его 422 тоже показывается.
- **Шапка** (`header__actions` в `App.tsx`): гость — кнопка «Войти» (открывает `AuthModal`); вошёл — логин и «Выйти» (как именно — меню, иконка, в настройках — по макету). «Выйти» → `logout()` → `switchUser(null)`.
- Телефон: шапка узкая — вид по макету, на 375 px ничего не наезжает.

## Критерии готовности
- [ ] Без входа страница работает как раньше, гостем: чат, «Мои дела», календарь, голос.
- [ ] Вход и регистрация — по макету; после входа «Мои дела», календарь и чат показывают данные учётки; после выхода — снова гость со своими записями; после смены пользователя лента пустая.
- [ ] Перезагрузка страницы сохраняет вход. Недействительный сохранённый токен → страница продолжает гостем и один раз говорит об этом.
- [ ] С токеном ни один запрос не уходит с `X-User-Id`; без токена — как раньше (проверить во вкладке «Сеть» браузера на чате, панели, календаре и голосе).
- [ ] Ошибки 401, 409, 422, 429 на входе и регистрации показаны текстом сервера; кнопка не нажимается дважды; ничего не падает молча.
- [ ] На стенде: вход под демо-учёткой на компьютере и на телефоне показывает одни и те же записи.
- [ ] Тесты из п. 3 проходят, `npm test` и `npm run build` — без ошибок; новых зависимостей в `package.json` нет.
- [ ] `docs/modules/frontend.md` обновлён (п. 6).
