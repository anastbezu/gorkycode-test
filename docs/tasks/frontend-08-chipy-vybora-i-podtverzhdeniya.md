## Цель
Когда ассистент спрашивает «Какую встречу перенести?», «Отменить все 4 дела?» или «На какое время поставить встречу?», под вопросом появляются кнопки ответа. Нажал — ответил, как если бы сказал голосом. Особенно важно на телефоне и при показе жюри: не нужно печатать «вторую».

## Контекст

### Откуда брать вид — строго
**Вид — только из макета. Ничего не придумывать.** Нет фрейма под состояние — не рисовать «по аналогии», а остановиться и спросить Асю. Если в макете и в этой постановке написано по-разному — права постановка (в ней учтён контракт), расхождение назвать Асе.

Макет: https://www.figma.com/design/W01oqMr1b3tCeq79iP2x94/?node-id=0-1, страница **«Экраны»** (страницу «Экраны · разобранные» не использовать). Каждый фрейм — в двух темах: « · светлая» и « · тёмная». Компонент чипа — «Чип выбора» на странице «Компоненты» (компонент «Чипс» устарел).

### Как показать макет агенту
Агент должен **сам сказать**, если фреймов у него нет: «Пришли мне PNG фреймов: …» — и не начинать вёрстку, пока не получит. Способы:
1. **Figma MCP** (если агент его поддерживает): ссылка на фрейм — правый клик по фрейму → Copy/Paste as → **Copy link to selection**. На бесплатном тарифе у Figma MCP маленький лимит вызовов — кончился, переходи к п. 2.
2. **Экспорт PNG.** Макет → страница «Экраны» → в панели слоёв слева выделить фреймы из таблицы (Shift + клик, обе темы) → справа внизу **Export** → «+» → **PNG**, **2x** → **Export N layers**. Отдать файлы агенту вместе с постановкой.
3. **Точный цвет, отступ, шрифт** — выделить элемент, справа **Inspect** (или Dev Mode). Цвета — из переменных `frontend/src/styles.css`.

### Что приходит и что отправлять — по контракту
`ChatResponse.awaiting` ([`api.md`](../contracts/api.md)):

| `awaiting` | Что показать под текстом ответа | Чип отправляет (как обычную реплику) |
|---|---|---|
| `"choice"` | нумерованный список `result.candidates` и под ним чип на каждую запись: номер в кружке, название, когда | «номер N» |
| `"confirm"` | нумерованный список `result.candidates` и две кнопки: «Да, все» (основная, цвет действия) и «Отмена» | «да, все» / «отмена» |
| `"time"` | четыре чипа: «09:00 утром», «13:00 в обед», «15:00 днём», «18:00 вечером» | «в 09:00», «в 13:00», «в 15:00», «в 18:00» |
| `"answer"`, `null` | быстрых ответов нет | — |

- Тексты для отправки и варианты времени — константы в одном месте (например `src/lib/quickReplies.ts`), рядом — ссылка на `api.md`.
- Номер в чипе и в списке — один и тот же: N-я запись `candidates`, с 1. Пользователь может и сказать «вторую» голосом — номера совпадают.
- Подтверждение бывает до 20 записей — список сворачивается по правилу длинного списка из frontend-06 (8 строк и «Показать ещё N»); кнопки «Да, все / Отмена» всегда видны под списком.
- Сейчас (после frontend-06) при `awaiting` и `candidates` показывается только текст — эту строку правила выбора вида заменяет таблица выше.

### Когда чипы нажимаются
- Чипы активны только у **последнего** ответа ассистента и пока не идёт отправка («Ассистент думает…»). У прежних ответов — вид «после ответа» по фрейму «Чат · выбор · после ответа».
- Нажатие = отправка реплики тем же путём, что ввод с клавиатуры (`send` в `App.tsx`): сообщение пользователя появляется в ленте с отправленным текстом, озвучка ответа — как обычно. Двойное нажатие не отправляет две реплики (как и сейчас для ввода).
- Какой чип был нажат — показывается по фрейму «после ответа», если там это видно; запоминается в сообщении ленты (переживает перезагрузку вместе с лентой, `src/lib/storage.ts`). Ответил текстом или голосом — ни один чип не выделен.
- Ответ с ошибкой сети или сервера — чипы остаются активными, можно нажать ещё раз.

### Стек — не меняется
React 19 + TypeScript, Vite, Vitest — как в [`modules/frontend.md`](../modules/frontend.md). **Новых зависимостей не добавлять.** Тип `ChatResponse.awaiting` в `src/api/types.ts` — четыре значения, один в один из контракта. Даты в чипах — `recordWhen` из `src/lib/dates.ts`. Бэкенд и контракты не трогать.

### Что меняется в коде
- `src/api/types.ts`, `src/lib/storage.ts` — тип `awaiting`; выбранный чип в сообщении.
- `src/lib/quickReplies.ts` (или как назовёшь) — что показать и что отправить по `awaiting`; чистые функции с тестами.
- `src/components/ResultView.tsx` (или новый компонент рядом) — список кандидатов, чипы, кнопки подтверждения.
- `src/App.tsx` — передать «последний ли это ответ», «идёт ли отправка» и функцию отправки.
- `src/styles.css` — по макету, обе темы.
- `docs/modules/frontend.md` — раздел «Быстрые ответы»: таблица `awaiting` → чипы → текст, когда чипы активны.

## Правила для агента
1. Вид — только по фреймам из таблицы. Нет фрейма — стоп, вопрос Асе. Нет PNG — попросить до начала работы.
2. Отправляемые тексты — только из таблицы контракта. Не «2», не «вторую», а «номер 2».
3. Никаких моков сервера в приложении, заглушек, пустых `catch`. Проверка `"confirm"` и `"time"` до agent-10 — только тестами на объектах `ChatResponse`.
4. Упростить или пропустить пункт — только спросив Асю **до** этого.
5. Перед кодом — пересказать Асе таблицу «что показать → что отправить». После каждой части (выбор, подтверждение, время) — остановка и показ.
6. Коммиты — `feat(frontend): …`, ветка `feature/frontend-08-chipy`.

## Тесты (Vitest)
- По каждому значению `awaiting`: что показывается и какие тексты отправляются.
- `"choice"` с 3 кандидатами — чипы «номер 1…3» в порядке `candidates`.
- `"confirm"` с 12 кандидатами — 8 строк, «Показать ещё 4», кнопки видны.
- Чипы неактивны у не последнего ответа и во время отправки.
- Сохранение и чтение выбранного чипа в ленте.

## Критерии готовности
- [ ] Выбор, подтверждение и время выглядят как их фреймы — светлая и тёмная тема, десктоп и телефон.
- [ ] Чип отправляет ровно текст из контракта; в ленте — сообщение пользователя с этим текстом.
- [ ] Чипы активны только у последнего ответа и не во время отправки; прежние — по фрейму «после ответа».
- [ ] На стенде выбор работает уже сейчас; подтверждение и время — после мержа agent-10.
- [ ] `npm test` и `npm run build` без ошибок; новых зависимостей нет; `docs/modules/frontend.md` обновлён.

## Проверка глазами
Для Аси и того, кто принимает. Стенд https://gorky.bond, демо-учётка, рядом — макет.
1. **Выбор.** Создать две встречи на сегодня, сказать «Перенеси встречу на пятницу» → список с номерами и два чипа. Сверить с «Чат · выбор · ждём ответа». Нажать второй чип → в ленте «номер 2», перенесена вторая встреча; чипы — как во фрейме «… после ответа».
2. **Подтверждение** (после agent-10). Создать 3–4 дела на завтра, сказать «Отмени всё на завтра» → список и «Да, все / Отмена». Сверить с «Чат · подтверждение отмены». «Отмена» → ничего не отменилось («Мои дела» те же). Ещё раз и «Да, все» → все отменены.
3. **Время** (после agent-10). «Назначь встречу с Игорем завтра» → четыре чипа времени. Сверить с «Чат · время встречи». Нажать «15:00 днём» → встреча на завтра 15:00.
4. **Старые ответы.** Пролистать ленту вверх — чипы прошлых вопросов не нажимаются.
5. **Телефон и тёмная тема** — пункты 1–3 на телефоне (или окно 390 px) и в тёмной теме: сверить с «Мобильная · …» и « · тёмная».
