# backend-03: изменение и статус записей, конфликты, состояние разговора

**Исполнитель:** Денис

## Цель
Дать агенту сервисы для бонусных сценариев: перенести или изменить запись, отметить выполненной, отменить, вернуть; предупредить о пересечении встреч; показать список без конца периода; хранить в состоянии разговора показанный список и последнее действие.

## Контекст
- Контракты: [`data-model.md`](../contracts/data-model.md) — новые поля `ConversationState` (`shown`, `last_action`, `pending_skipped`) и раздел «Правила состояния»; [`agent-tools.md`](../contracts/agent-tools.md) — `UpdateRecord`, `SetStatus`, `UndoLast`, «Проверки кода», `ListRecords.date_to = None`, `ActionResult.restored`. Pydantic-схемы в `backend/schemas/` приведи к контракту в своей ветке.
- **Транзакции меняются: один коммит на реплику.** Сервисы больше не делают `commit` сами — коммитит вызывающий (маршрут или агент) один раз в конце реплики. Причина: запись и состояние разговора (`last_action` с прежними значениями) должны сохраняться вместе, иначе «верни» не откатит изменение. Касается и существующих `create_record`, `save_conversation_state`.
- **Изменение записи** возвращает и новую запись, и прежние значения изменённых полей — агент кладёт их в `last_action.before`.
- **Конфликт:** при создании и переносе встречи — другие активные встречи пользователя, пересекающиеся по времени; у встречи без `end` для проверки 60 минут (в запись не пишется). Запись сохраняется, пересечения — в `ActionResult.conflicts`. Точный дубль (активная запись с тем же названием и `start`) не создаётся.
- **Список без конца периода:** `date_to = None` — без верхней границы, в конце — активные записи без даты (`list_undated_records` уже есть).
- Миграция `conversation_states` под новые поля.

## Критерии готовности
- [ ] Миграция применяется на чистой БД и на БД с данными; новые поля состояния сохраняются и читаются.
- [ ] Сервисы не коммитят сами; тест: при ошибке изменение записи и состояние откатываются вместе.
- [ ] Изменение записи возвращает прежние значения; смена статуса работает для `done`, `cancelled`, `active`.
- [ ] Встреча на занятое время создаётся и возвращает `conflicts`; встреча без конца пересекается со встречей, начатой через 30 минут; дубль не создаётся.
- [ ] Список с `date_to = None` отдаёт будущие записи и записи без даты, без отменённых.
- [ ] Смоук-тесты `pytest` на новые сервисы.
