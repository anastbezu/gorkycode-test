# agent-04: сценарии списков за период и смыслового поиска

**Исполнитель:** Илья

## Цель
Реализовать обработку запросов на календарные списки дел (Сценарий 3: `ListRecords` с генерацией лаконичного голосового резюме) и поиск по архиву дел (Сценарий 4: `SearchRecords` с интеграцией контракта поиска Родиона).

## Контекст
- **Стек:** Python 3.13, Pydantic v2 (по техническим решениям в `docs/decisions.md`).
- **Контрактная основа:** Контракты [`docs/contracts/agent-tools.md`](../contracts/agent-tools.md), [`docs/contracts/search.md`](../contracts/search.md), [`docs/contracts/api.md`](../contracts/api.md).
- **Зависимости:** Опирается на клиент агента ([agent-02](agent-02-klient-llm-i-vyzov-tulov.md)), сервисы выборки Дениса ([backend-02a](backend-02a-servisy-zapisej.md)) и контракт `search` Родиона.
- **Сценарий 3: Календарный список за период (`ListRecords`):**
  - Пользовательские формулировки: *«Что у меня на сегодня?»*, *«Какие планы на завтра?»*, *«Покажи встречи на этой неделе»*.
  - LLM вызывает `ListRecords(date_from=..., date_to=..., types=...)`.
  - Агент запрашивает сервис Дениса `list_records_for_period(user_id, action)`.
  - **Генерация голосового резюме (`ChatResponse.reply`):**
    Текст ответа должен быть кратким и естественным для восприятия на слух голосовым синтезатором речи:
    - Если записей нет: *«На этот период ничего не запланировано»*.
    - Если 1–3 записи: перечисление с указанием времени (*«На сегодня у вас 2 дела: в 10:00 планёрка и в 15:00 созвон с клиентом»*).
    - Если записей много (>3): агрегированное саммари (*«На сегодня у вас 6 дел. Первое — планёрка в 10:00»*).
    - Для дел на весь день (`all_day=True`) не озвучивать время 00:00, говорить: *«в течение дня: покупка билетов»*.
  - В поле `ChatResponse.result.items` передаётся полный список объектов `Record` для отображения в интерфейсе Насти.
- **Сценарий 4: Смысловой поиск по архиву (`SearchRecords`):**
  - Пользовательские формулировки: *«Найди задачу про договор»*, *«Когда созвон с юристами?»*, *«Поищи старые напоминания по налогам»*.
  - LLM вызывает `SearchRecords(query="договор", filters=SearchFilters(...))`.
  - Агент обращается к функции контракта поиска:
    `search(user_id: UUID, query: str, filters: SearchFilters, limit: int = 10) -> list[SearchHit]`.
  - *Примечание:* До завершения векторного модуля Родиона напиши временную заглушку `search()`, которая выполняет поиск по подстроке в таблице `records` (`ILIKE %query%`).
  - **Результат поиска:**
    - Если список пуст: `reply = "По запросу '...' ничего не найдено"`, `result = ActionResult(ok=True, items=[])`.
    - Если найдены совпадения: формируется краткий текст (*«Найдена встреча с юристами на 28 октября»*) и передаются элементы в `result.items`.
    - Если найдено ровно 1 совпадение: идентификатор записи автоматически выставляется в фокус диалога: `state.focus_record_id = hit.record.id`, чтобы пользователь мог сразу сказать *«перенеси её»*.

### Источники для изучения
- **Паттерн генерации кратких голосовых реплик по списку событий:** голосовой навык [OpenVoiceOS Alerts](https://github.com/OpenVoiceOS/ovos-skill-alerts/tree/master/locale/ru-ru) (директория диалогов `locale/ru-ru/`). Посмотри, как фразы ответов адаптируются под количество дел, исключая монотонное зачитывание десятков пунктов.
- **Интерфейс функции поиска по смыслу:** утверждённый контракт проекта [`docs/contracts/search.md`](../contracts/search.md). Сигнатура функции `search()`, структура `SearchHit` и правила предварительной фильтрации до векторного поиска.

## Критерии готовности
- [ ] Отрабатывает Сценарий 3: запрос «что у меня на сегодня» возвращает отсортированный список дел и естественный текст для озвучивания голосом.
- [ ] При отсутствии дел возвращается вежливый текст без пустых списков или ошибок.
- [ ] Записи на весь день (`all_day=True`) озвучиваются без упоминания времени 00:00.
- [ ] Отрабатывает Сценарий 4: запрос со смысловым поиском передаёт `query` и фильтры в контрактную функцию `search()`.
- [ ] При единственном найденном результате его `id` фиксируется в `state.focus_record_id`.
- [ ] Написан 1 быстрый смоук-тест через `pytest`, проверяющий форматирование голосового ответа по списку из 2 записей.

## На усмотрение исполнителя
Алгоритм сокращения голосовых фраз при большом количестве дел (более 5 записей), формулировки диалоговых ответов.
