# agent-01: системный промпт и схемы инструментов

**Исполнитель:** Давид

## Цель
Заменить тяжеловесный системный промпт (126 строк) компактным: роль, календарный контекст и общие правила; вынести детальные правила нормализации дат и времени в описания полей (`Field(description=...)`) Pydantic-схем с обязательным шаблоном-примером формата ISO 8601, и реализовать генератор опорного календарного контекста.

## Контекст
- **Стек:** Python 3.13, Pydantic v2 (по техническим решениям в `docs/decisions.md`).
- **Контрактная основа:** Контракт [`docs/contracts/agent-tools.md`](../../contracts/agent-tools.md) и принятое решение об одном вызове LLM на реплику пользователя (`docs/decisions.md`).
- **Анализ текущей ветки `feature/agent_david-01-system-prompt`:**
  - В файле `backend/agent/system_prompt.py` системный промпт раздут до 126 строк.
  - Избыточные фрагменты, подлежащие удалению:
    1. Четырёхкратное дублирование времени: одновременно передаются `Сейчас: пятница, 24 октября...`, `Текущие дата и время в ISO 8601...`, `Сегодня: 2026-10-24`, `День недели: пятница`.
    2. Защита от prompt injection: параноидальные оговорки занимают контекст и размывают внимание модели в прототипе ассистента.
    3. Инструкции второго хода: требования *«подтверждай действие после ответа тула»* и *«объясняй ошибки тулов»* предполагают второй вызов LLM после действия, а у нас один вызов LLM на реплику (`docs/decisions.md`). Кто пишет текст ответа — шаблон в коде или LLM в том же вызове — решаете вы с Ильёй и описываете в `docs/modules/agent.md`.
- **Архитектурный принцип распределения инструкций:**
  Правила, которые относятся к одному полю, живут в описании этого поля, а не в системном промпте: так промпт не раздувается, а правило стоит рядом с полем, которое модель заполняет. Поэтому правила нормализации полей («утром = 09:00», «до конца недели = вс 23:59:59», очистка от слов «напомни») должны находиться внутри параметров инструментов в Pydantic, а в системном промпте остаётся только глобальная роль и календарные якоря.
- **Обязательный строковый шаблон формата дат (ISO 8601):**
  Модели LLM без конкретного шаблона-примера часто путают часовые пояса (возвращают `Z` вместо локального пояса) или опускают время (`2026-10-25` вместо полной даты со временем), что ломает валидацию Pydantic `AwareDatetime`. Поэтому во всех описаниях дат и в системном промпте **обязательно указывается строковый пример** со смещением пояса пользователя: пояс приходит из браузера (`timezone` в `ChatRequest`), поэтому смещение в примере вычисляется из него, а не зашивается. Для `Europe/Moscow` пример выглядит так: `2026-10-25T15:00:00+03:00`.
- **Компактный системный промпт (`backend/agent/system_prompt.py`):**
  - Функция `build_compact_system_prompt(now: datetime, timezone_name: str) -> str`:
    - Вычисляет день недели на русском языке (понедельник ... воскресенье).
    - Вычисляет опорные даты: даты всех дней текущей и следующей недели с днями недели — чтобы LLM не считала «в пятницу» сама (`docs/decisions.md`, разбор дат).
    - Формирует компактный текст (не более 15 строк):
      ```
      Ты голосовой ассистент для задач, встреч и напоминаний.
      Помогай пользователю, вызывая ровно один подходящий инструмент на запрос.

      Контекст:
      - Текущее время: {now.isoformat(timespec="seconds")} ({weekday})
      - Часовой пояс: {timezone_name}
      - Опорные даты: {дни текущей и следующей недели с датами}

      Правила:
      1. Вызывай инструмент строго по схеме его параметров. Не придумывай данные и действия.
      2. Все даты и время возвращай в полном формате ISO 8601 со смещением пояса пользователя, например: {пример со смещением пользователя}.
      3. Относительные дни («завтра», «в пятницу») отсчитывай от контекста. «В пятницу», если сегодня пятница, означает следующую неделю.
      4. Если для встречи или задачи критически не хватает обязательных данных (нет времени встречи), вызывай инструмент ask_user. Не угадывай скрытые параметры.
      ```
- **Схемы 4 инструментов (`backend/agent/tools.py`):**
  - Классы действий — из `backend/schemas` (контракт [`docs/contracts/agent-tools.md`](../../contracts/agent-tools.md); у Дениса они уже в ветке `feature/backend-02-pydantic-schemas`, файл `backend/schemas/actions.py`). В агента их не копировать — описания полей дописываются в сами схемы:
    - `CreateRecord`: поля `action`, `type`, `title`, `start`, `end`, `time_given`, `deadline`. В `description` полей `start`, `end`, `deadline` — строковый пример формата со смещением пользователя, правила нормализации («утром» = 09:00, «в N» = N:00, «до конца недели» = воскресенье 23:59:59) и требование ставить `null`, если время не названо (НЕ 00:00!).
    - `ListRecords`: поля `action`, `date_from`, `date_to`, `types`. Чёткое описание в `description` класса: *«Показать список записей за явный календарный интервал ('что у меня сегодня', 'планы на неделю'). НЕ использовать для поиска по теме»*.
    - `SearchRecords`: поля `action`, `query`, `filters`. В `description` поля `query`: очистка от слов «найди», «поищи», «задачу про».
    - `AskUser`: поля `action`, `question`, `missing: list[str]`.
    - Дискриминированное объединение `LLMAction`.
  - Реализуй функцию `get_agent_tools() -> list[dict]`, которая экспортирует JSON Schema этих Pydantic-моделей в стандартный формат OpenAI Tools (`[{"type": "function", "function": {"name": ..., "description": ..., "parameters": ...}}]`).

### Источники для изучения
- **Пример формата даты прямо в описании параметра:** MCP-сервер Google Календаря [google-calendar-mcp](https://github.com/nspady/google-calendar-mcp/blob/f7f379a5971fafbc79432abdc4b62412a04e3ffa/src/tools/registry.ts) (файл `src/tools/registry.ts`, описания полей `start`, `end`, `timeZone`). В описаниях аргументов прописан формат с примером. Взять только этот приём: у них время передаётся без смещения, а пояс — отдельным полем `timeZone`, у нас наоборот — смещение внутри даты.
- **Правила разбора — в описании аргумента функции:** русский голосовой ассистент [Irene-Voice-Assistant](https://github.com/janvarev/Irene-Voice-Assistant/blob/adb469ed045bfbc2de30b9b0bfa773cd2f7250bc/plugins_inactive/plugin_ai_timer.py) (файл `plugins_inactive/plugin_ai_timer.py`, плагин таймера через LLM). Системного промпта в плагине нет: правила разбора чисел и времени («полминуты = 30 секунд») и значения по умолчанию записаны прямо в описании аргумента функции.

## Критерии готовности
- [ ] В системном промпте только роль, календарный контекст и общие правила: нет дублей текущего времени и правил, которые уже есть в описаниях полей.
- [ ] Опорные даты — все дни текущей и следующей недели — вычисляются корректно относительно часового пояса пользователя; пример формата в промпте и описаниях — со смещением этого пояса.
- [ ] Все 4 действия контракта `docs/contracts/agent-tools.md` берутся из `backend/schemas` (без копий) и имеют описания полей с примером формата даты.
- [ ] Функция `get_agent_tools()` возвращает валидный список словарей инструментов для вызова через OpenAI API.
- [ ] Написано 2 быстрых смоук-теста через `pytest` на чистом Python:
  1. Тест генерации промпта (опорные даты двух недель и смещение пояса пользователя).
  2. Тест парсинга валидного JSON в модель `CreateRecord` с проверкой парсинга смещения пояса.

## На усмотрение исполнителя
Вспомогательные форматировщики дат, названия русскоязычных констант дней недели.
