## Цель
Ассистент находит запись для изменения так, что никогда не меняет чужую, и честно говорит «точно не нашёл», показывая похожие, — и в поиске, и при изменении.

## Контекст

### Что было и что меняется
В agent-07, раздел «Цель изменения: как найти запись», для `TargetRef.text` написано: вызвать `search()` по `text`, затем самому упорядочить кандидатов (совпали дата и время → время → название → остальные), будущие раньше прошедших. Ресёрч на нашем датасете показал, что это плохо:
- **Поиск по смыслу для цели переспрашивает зря.** Пример: у пользователя «Встреча с дизайнером» в пятницу 15:00, «Встреча с дизайнером» в понедельник 11:00 и «Созвон с дизайнером» в пятницу 12:00. «Отмени встречу с дизайнером в пятницу»: по смыслу «созвон» близок к «встрече», в пятницу находятся две записи — ассистент спрашивает «какую?», хотя пользователь назвал ясно. В замере — 11 лишних переспросов на 24 цели.
- **Нечёткое сравнение меняет чужое.** «Отмени созвон с Севером по CRM», а такой записи нет — есть «Созвон с Севером по новому продукту». Нечёткое сравнение (как в OVOS) находит её и отменяет. В замере — 2 раза.
- **«Будущие раньше прошедших»** не делает ни один из разобранных ассистентов, а фильтр по статусу и так отсекает прошедшие (у импортированных прошедших записей статус `done`). Правило убирается.

Теперь цель ищет **модуль поиска** функцией `find_target()` ([`search.md`](../../contracts/search.md)): в названии должны быть все значимые слова описания, затем сужение по названному времени. Похожие по смыслу приходят отдельно — только чтобы спросить. Твоя часть — вызвать её и решить, что делать с исходом. Сам записи не ищешь и кандидатов не сортируешь.

### Как разрешается `TargetRef` теперь
- `index` и `focus` — как в agent-07, без изменений.
- `text`, `when`, `filters` → `find_target(db, user_id, text, when, filters, statuses)`; `statuses` — `[active]`, для «верни в активные» и «не выполнено» — `[done, cancelled]`.
- Исход:
  - `exact` — одна запись → исполнить;
  - `exact` — несколько → ничего не менять, выбор, как в agent-07: `candidates`, `shown`, `pending`, `awaiting="choice"`;
  - `exact` пуст, `similar` не пуст → ничего не менять; `similar` — в `candidates` и `shown`, `awaiting="choice"`, вопрос: «Точно такой нет. Может, это „Созвон с Севером по новому продукту“?» (одна) или «…Может, одна из этих: 1) … 2) …?». Ответ «да» на одну, «вторую», нажатие чипа — модель возвращает действие с `index`, исполняется как обычный выбор. **Исполнять похожую без ответа пользователя нельзя.**
  - оба пусты → `ok=False`, «Не нашёл встречу с дизайнером».
- **Несколько записей одной командой** (`all=True`) — только `exact` из `find_target()` (передавай `limit=21`; пришла 21 запись — «Слишком много, уточните»); `similar` для массового действия не используется.
- Прошедшая запись в `exact` — исполняется, ответ называет её дату («Отменил встречу 05.03.2026…»), как и было.

### Ответ на поиск: «похожие»
`search()` теперь отдаёт у каждого результата `match`: `"exact"` или `"similar"` — в одном ответе все одного вида ([`search.md`](../../contracts/search.md), «`search()` — вопрос пользователя»). Шаблон ответа на поиск (`backend/agent/search_replies.py`, твоя agent-04) различает:
- `exact` — как сейчас;
- `similar` — «Точно не нашёл „договор аренды“. Похожие: …» — и записи в `result.records` с номерами, как обычно;
- пусто — как сейчас.
`SearchHit.match` уже есть в `backend/schemas/search.py` (по умолчанию `"exact"` — заглушка поиска по подстроке продолжает работать).

## Критерии готовности
- [ ] `TargetRef.text` разрешается только через `find_target()`; своего поиска записей и своей сортировки кандидатов в агенте нет.
- [ ] Четыре исхода (одна, несколько, только похожие, ничего) дают действие, выбор, вопрос «может, эту?» и «не нашёл» соответственно; похожая запись без ответа пользователя не меняется — есть тест.
- [ ] После вопроса «может, эту?» ответ «да», «вторую» и нажатие чипа исполняют действие над выбранной записью.
- [ ] Массовая отмена берёт только точные записи; больше 20 — просьба уточнить.
- [ ] Ответ на поиск с `match="similar"` говорит «точно не нашёл» и показывает похожие с номерами.
- [ ] Тесты `pytest` без сети: `find_target()` и `search()` подменены ответами по контракту.
- [ ] На стенде после search-01: «Отмени созвон с Севером по CRM» не отменяет «Созвон с Севером по новому продукту», а спрашивает.
- [ ] `docs/modules/agent.md` — как агент разрешает цель и отвечает на «похожие».
