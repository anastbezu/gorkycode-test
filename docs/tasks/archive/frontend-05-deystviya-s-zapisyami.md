## Цель
Всё, что ассистент умеет голосом с записью, можно сделать руками: открыть запись из «Моих дел», календаря или ответа ассистента — перенести, отметить выполненной, удалить (и тут же вернуть), а также создать новую запись без чата.

## Что решено и почему
- Кнопки работают **без LLM**: отдельные эндпоинты поверх тех же сервисов, что у агента. Кнопка не отправляет фразу в чат — это был бы вызов модели на каждый клик и риск, что она поймёт не так.
- **Удаление мягкое**, как голосовое «отмени»: запись получает статус `cancelled` и пропадает из «Моих дел» и календаря, «Вернуть» возвращает её (`active`). Насовсем её стирает только чистка через 30 дней.
- **Пересечение не мешает сохранить**: встреча сохраняется, интерфейс предупреждает, с чем пересеклась, — как в чате.
- **Ручная правка не меняет разговор**: номера в ленте остаются прежними (пользователь может дальше сказать «перенеси вторую»), сообщения не добавляются. Сервер сам забывает для этой записи последнее голосовое изменение, чтобы «верни» в чате не откатило её поверх ручной правки.

## Стек — не меняется
React 19 + TypeScript, Vite, тесты Vitest — как в [`modules/frontend.md`](../../modules/frontend.md). **Новых зависимостей не добавлять**: выбор даты и времени — встроенные поля браузера `<input type="date">` и `<input type="time">` (работают на телефоне и в Safari), окно — по образцу `components/SettingsModal.tsx`, стили — в `styles.css` по макету. Даты — только через `src/lib/dates.ts`, без `toISOString()` (он даёт UTC без пояса пользователя, а сервер ждёт смещение пояса). Бэкенд не трогать.

## Контракт — что важно клиенту
```ts
// добавить в src/api/types.ts — один в один из api.md
export interface CreateItem {
  type: RecordType; title: string;
  start?: string | null; end?: string | null;   // ISO 8601 со смещением
  time_given?: boolean;                         // false — «весь день», start = полночь дня
  deadline?: string | null;
}
export interface UpdateItem {                   // только меняемые поля
  title?: string; start?: string; end?: string; time_given?: boolean; deadline?: string;
}
export interface SetItemStatus { status: RecordStatus }  // done | cancelled | active
```
- `POST /api/items?tz=<пояс>` (тело `CreateItem`) → 201 `ActionResult`.
- `PATCH /api/items/{id}?tz=<пояс>` (тело `UpdateItem`) → 200 `ActionResult`.
- `POST /api/items/{id}/status?tz=<пояс>` (тело `SetItemStatus`) → 200 `ActionResult`.
- В ответе: запись — `records[0]`, пересечения встречи — `conflicts` (может быть пусто).
- 422 — проверка не прошла, `detail` для пользователя («дата в прошлом», «такая запись уже есть», у встречи нет времени) — показать как есть. 404 — записи нет (удалена на другом устройстве и стёрта, чужая) — сказать и перечитать список. 400 и 401 — как у остальных запросов.
- Убрать дату или срок этим API **нельзя** (`null` в `UpdateItem` значит «не менять») — в окне нет кнопки «убрать дату».
- Пример дат: встреча 31 октября в 15:00 в Москве — `start: "2026-10-31T15:00:00+03:00"`; задача на 31 октября без времени — `start: "2026-10-31T00:00:00+03:00", time_given: false`.

## Что сделать

### 1. Даты — `src/lib/dates.ts`
- `localDateTimeIso(key: string, time: string): string` — день `YYYY-MM-DD` и время `HH:MM` → ISO со смещением этой даты, по образцу `localMidnightIso` (смещение — своё для даты, летнее время меняет его).
- Обратное — значения для полей формы из записи: день (`dayKey(new Date(record.start), tz)`) и время `HH:MM` (через `wallTime`). Запись `all_day` — время пустое, «весь день» отмечен.
- Тесты в `dates.test.ts`: обычная дата, дата на переходе времени, полночь, «весь день».

### 2. Клиент — `src/api/client.ts`
Три функции по образцу `fetchItems` (тот же `asUser`, `recoverBadUser`, `parse`, таймаут 30 с, параметр `tz`):
- `createItem(body: CreateItem, tz: string): Promise<ActionResult>`;
- `updateItem(id: string, body: UpdateItem, tz: string): Promise<ActionResult>`;
- `setItemStatus(id: string, status: RecordStatus, tz: string): Promise<ActionResult>`.
Ошибки — те же два вида, что у чата: «результат неизвестен» (сеть, 5xx — сервер мог успеть сохранить) и «сервер не принял» (4xx с `detail` — ничего не сделано). Тесты в `client.test.ts`: метод, адрес, `tz`, тело, разбор 201/200/404/422.

### 3. Сборка тела запроса — отдельная чистая функция
Например `src/lib/recordForm.ts`: значения формы → `CreateItem` или `UpdateItem`. Правила:
- **Перенос**: в `UpdateItem` — только изменённые поля. Сменили день или время — `start` и `time_given`; отмечено «весь день» — `start` = полночь дня, `time_given: false`. Для встречи `end` **не отправлять**: сервер сам сдвинет конец и сохранит длительность. Сменили срок задачи — `deadline`. Ничего не поменяли — запрос не отправлять, кнопка «Сохранить» неактивна.
- **Создание**: тип обязателен; название — без пробелов по краям, пустое — нельзя. Встреча — день и время обязательны. Напоминание — день обязателен, время — по желанию. Задача — день и срок необязательны (задача «без срока» допустима). Срок без времени — конец дня: `localDateTimeIso(key, '23:59')`.
- Тесты на каждое правило.

### 4. Окно записи — новый компонент `src/components/RecordDialog.tsx`
Модальное окно по образцу `SettingsModal` (`modal`, `modal__dialog`, закрытие по фону и крестику). Два режима:
- **Существующая запись** (открывается кликом по карточке): тип, название, когда, статус. Кнопки:
  - «Перенести» — поля дня, времени, «весь день», у задачи — срок; «Сохранить» → `updateItem`;
  - «Выполнено» (у активной) или «Не выполнено» (у выполненной) → `setItemStatus` с `done` или `active`;
  - «Удалить» → `setItemStatus(id, 'cancelled')`, окно закрывается, показывается уведомление «Удалено · Вернуть» (п. 6).
- **Новая запись**: тип (задача, встреча, напоминание), название, день, время, «весь день», у задачи — срок; «Создать» → `createItem`. Открытая из календаря — день заранее равен выбранному дню.
- Пока запрос идёт — кнопки неактивны (двойной клик не создаёт две записи). 422 и 404 — текст под формой, окно не закрывается. «Результат неизвестен» — текст «Нет ответа от сервера, проверьте список» и перечитать список.
- После успеха: если в `conflicts` что-то есть — показать «Пересекается с: <название, время>» (вид по макету) и только потом закрыть по кнопке; иначе закрыть сразу.

### 5. Где открывается окно
- **Карточки** — `TaskCard` в `components/TasksPanel.tsx` (её же использует календарь): добавить необязательный `onOpen?: (record) => void`; карточка с ним — кнопка (клик и Enter открывают окно, `cursor: pointer`).
- **«Мои дела»** (`TasksPanel`) и **день в календаре** (`CalendarView`) — передают `onOpen`; кнопка «Создать» (место — по макету) открывает окно новой записи.
- **Ответ ассистента** (`components/ResultView.tsx`): карточки созданных записей и строки нумерованного списка тоже открывают окно. Номер строки не меняется.
- Состояние «какое окно открыто» — в `App.tsx` (одно окно на страницу), туда же — функция «после действия» (п. 7).

### 6. Уведомление «Удалено · Вернуть» — новый компонент `src/components/Toast.tsx`
Внизу экрана, не перекрывает поле ввода на телефоне. «Вернуть» → `setItemStatus(id, 'active')` → перечитать список. Сколько держится — по макету (если не указано — 8 секунд). Новое удаление заменяет прежнее уведомление.

### 7. После любого успешного действия
- Перечитать «Мои дела» (`panel.load()` из `App.tsx`) и календарь (дать `CalendarView` способ перечитаться — например, счётчик-проп `reloadKey`, по изменению которого он вызывает свой `load`).
- **Обновить запись в ленте**: в `chat.messages` во всех ответах ассистента заменить запись с тем же `id` в `result.records` на `records[0]` из ответа — чтобы карточка и строка списка показывали новое время или «выполнено». Порядок и номера не трогать; удалённая запись в списке ленты остаётся на своём месте с отметкой «удалено» (иначе номера сдвинутся, и «вторая» станет другой записью). В `ResultView` — отметка для статуса `cancelled` рядом с существующей «выполнено».
- В чат ничего не отправлять, озвучку не включать.

## Критерии готовности
- [ ] Из «Моих дел», календаря и ответа ассистента запись открывается в окне; перенести (день, время, «весь день», срок задачи), выполнено и не выполнено, удалить с «Вернуть» — работают по макету.
- [ ] «Создать» из «Моих дел» и календаря создаёт задачу, встречу и напоминание; из календаря день подставлен.
- [ ] После каждого действия «Мои дела» и календарь показывают новое состояние; в ленте карточка и строка обновились, номера не сдвинулись, новых сообщений нет.
- [ ] Перенос встречи на занятое время сохраняется и показывает пересечение.
- [ ] Ошибки 422 и 404 показаны текстом сервера, окно не закрылось; при сбое сети — «результат неизвестен», список перечитан.
- [ ] Двойной клик не создаёт двух записей и не шлёт два запроса.
- [ ] На стенде (Chrome на компьютере и телефон): перенести встречу кнопкой → удалить → «Вернуть» → сказать в чате «верни» — ручной перенос не откатился.
- [ ] Тесты из п. 1–3 проходят, `npm test` и `npm run build` — без ошибок; новых зависимостей в `package.json` нет.
- [ ] `docs/modules/frontend.md` обновлён (п. 8).

## На усмотрение исполнителя
Вид по макету, точные имена внутренних функций, как разложить код внутри файлов, как `CalendarView` узнаёт о перечитывании. Структура выше (окно записи, отдельная функция сборки тела, обновление записи в ленте без сдвига номеров, встроенные поля даты, без новых зависимостей) — не на усмотрение.
