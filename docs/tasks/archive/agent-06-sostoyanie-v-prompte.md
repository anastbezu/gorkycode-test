# agent-06: состояние разговора в промпте, ссылки на записи, смена темы, отказ

**Исполнитель:** Давид. Делается сразу после [agent-03](agent-03-slot-filling-i-kontekst.md), поверх её кода.

## Цель
Ассистент понимает реплики, которые опираются на прошлые: «перенеси вторую», «отмени её», «нет, не в 15, а в 16», «верни», «в 16» после постороннего вопроса, «не надо» посреди уточнения. Истории сообщений в промпте по-прежнему нет: между репликами всё помнит сервер в состоянии разговора, а модель получает его коротким текстом.

Эта задача отвечает за **жизненный цикл состояния**: что попадает в промпт, как состояние меняется после каждой реплики, что код делает до вызова модели. Новые действия (изменить, сменить статус, откатить, справка) и поиск записи-цели — в [agent-07](agent-07-izmenenie-status-otkat.md) у Ильи; он вызывает то, что сделаешь ты.

## Контекст

### Что меняется относительно agent-03
- agent-03 предписывала: «модель передаёт `record_id` из фокуса». **Больше нет:** id записей в промпт не попадают, модель ссылается на запись номером из показанного списка или признаком «в фокусе» (`TargetRef.index`, `TargetRef.focus`), а id подставляет код. Так модель не может выдумать или исказить UUID. Если в твоём коде agent-03 строка фокуса содержит id — убери id из неё.
- Черновик (`pending`, `merge_pending`, `clear_pending`) и строка черновика в промпте из agent-03 остаются — эта задача их расширяет.

### Порядок обработки реплики
1. **Загрузить состояние** разговора.
2. **Отказ — до модели.** Если `awaiting` не пуст (ассистент ждёт ответа или выбора) и вся реплика после нормализации (регистр, знаки препинания, лишние пробелы) — одна из фраз отказа из `data-model.md` («не надо», «забудь», «отмена», «проехали», «забей», «неважно», «отбой», «стоп»): сбросить черновик, кандидатов и ожидание, ответить шаблоном («Хорошо, не ставлю» / «Хорошо, ничего не меняю»), модель **не вызывать**. «Отмени встречу с Иваном» — не отказ, а команда: сверяется вся фраза, не подстрока. Список взят из русского набора Home Assistant (ссылка ниже); дополнить его — через правку контракта.
3. **Собрать текст состояния** и добавить его в системный промпт (формат ниже).
4. **Вызов модели** — как сейчас.
5. **Исполнение** — `execute` (создание — agent-05, новые действия — agent-07).
6. **Обновить состояние** по результату — одна функция для всех действий (правила ниже). agent-07 вызывает её же и передаёт прежние значения для `last_action.before`.
7. **Ответ** по шаблону; если черновик пропущен — добавить напоминание о нём.

### Текст состояния в промпте
Не больше ~12 строк, без id, даты — в поясе пользователя. Пустое состояние — ни одной строки. Например:
```
Показано: 1) Демо проекта по сайту 22.10 10:00  2) Встреча с Иваном 22.10 15:00  3) Отчёт до 25.10
В фокусе: Встреча с Иваном 22.10 15:00
Последнее действие: создана встреча «Встреча с Иваном» 22.10 15:00
Черновик: встреча «Встреча с Дмитрием» на 23.10, не хватает: start
```
- «Показано» — записи из `shown` по порядку, не больше 10; номер в строке — номер записи на экране. Номер дальше десятого («перенеси пятнадцатую») модель всё равно передаёт в `index`, код переводит его по `shown`. У каждой — название и когда (время, «весь день», «до …» для срока, «без даты»); выполненные и отменённые помечены.
- В правила промпта добавить, как ссылаться: «вторую» — номер из «Показано», «её», «эту», поправка сразу после действия — фокус; id не писать.
- Если запись из `shown` или фокуса уже удалена из базы — строку пропустить.

### Обновление состояния после действия
- **Список, поиск, выбор из кандидатов** перезаписывают `shown` — всеми записями, которые интерфейс показывает под номерами: `ActionResult.candidates`, если они не пустые, иначе `ActionResult.records`, в том же порядке ([`api.md`](../../contracts/api.md), «Правила»; [`data-model.md`](../../contracts/data-model.md), «Правила состояния»). «Вторую» — вторая строка на экране. Текст ответа (`reply`, он же озвучивается) может назвать только несколько записей и свернуть одинаковые тексты («созвон с Севером — 7 раз») — на `shown` это не влияет: в `shown` все записи по отдельности.
- **Фокус** — запись, если создана, изменена или показана ровно одна; показано несколько или ни одной — фокус снимается.
- **`last_action`** — после каждого изменяющего действия: создание (`before` пустой), изменение и смена статуса (`before` — прежние значения, их передаёт agent-07). Список, поиск, справка и вопрос его не трогают.
- **Несколько созданий в одной реплике** (agent-07): `last_action.record_ids` — все созданные, фокуса нет.

### Черновик и смена темы
- «Реплика про черновик» — модель вернула `create_record` того же типа, что черновик, или `ask_user`. Всё остальное — «не про черновик».
- Реплика не про черновик **выполняется**, черновик остаётся, `pending_skipped = True`, `awaiting` остаётся `answer`, к ответу добавляется напоминание шаблоном: «Встречу с Иваном так и не поставил — на какое время?».
- Следующая реплика снова не про черновик (`pending_skipped` уже `True`) или новое создание другого типа — черновик сброшен (`pending`, `missing`, `pending_skipped`, `awaiting`), напоминания нет.
- Реплика про черновик — `pending_skipped = False`, дальше как в agent-03.
- Тексты шаблонов в этой задаче (напоминание о черновике, ответ на отказ) показывают смысл; окончательные формулировки — по `docs/assistant-texts.md` Маши ([product-03](product-03-teksty-assistenta.md)), когда он появится. `reply` — один текст для чата и голоса ([`api.md`](../../contracts/api.md)).
- Пример ([`test-cases.md`](../../test-cases.md) 3.13–3.15): «Поставь встречу с Иваном завтра» → «На какое время?» → «А что у меня завтра?» → список на завтра и напоминание → «В 16» → встреча 22.10 16:00. А если между ними два посторонних вопроса — «в 16» уже ни к чему не относится, ассистент переспрашивает.

### Правила дат и времени
Описания полей в схемах уже обновлены (`start`, `deadline`, `ListRecords.date_to`, `types`). В системный промпт перенести правила из раздела «Правила» `agent-tools.md`, которых нет в описаниях: «в следующую пятницу» — пятница следующей недели; «эта неделя» — с понедельника; «что у меня вечером» — интервал [18:00, 24:00); «на выходных» — суббота, «в конце месяца» — последний день месяца. Каждое правило — одна короткая строка: промпт должен остаться компактным (сейчас ~360 токенов).

## Критерии готовности
- [ ] Текст состояния собирается из `ConversationState` по формату выше; без id; пустое состояние — ни строки; смоук-тест на сборку из готового состояния.
- [ ] После списка, поиска и выбора `shown` совпадает с `candidates` (если есть), иначе с `records` ответа — те же записи в том же порядке, без группировки; после одной созданной или найденной записи — фокус; после нескольких — фокуса нет.
- [ ] `last_action` пишется после создания; функция обновления состояния принимает прежние значения для изменения и статуса (для agent-07).
- [ ] Отказ при `awaiting` сбрасывает черновик без вызова LLM (тест с подменённым `get_action`, который не должен вызываться); «отмени встречу с Иваном» отказом не считается.
- [ ] Кейсы [`test-cases.md`](../../test-cases.md) 3.11 и 3.13–3.15 проходят.
- [ ] Кейсы раздела 9 («Даты и время») и 2.23а–2.23ж проверены на модели по умолчанию; что не прошло — записано в `docs/modules/agent.md`.
- [ ] `docs/modules/agent.md` описывает порядок обработки реплики и формат текста состояния.

## На усмотрение исполнителя
Точный формат строк состояния, где собирается промпт, устройство функции обновления состояния, нормализация реплики для сверки отказа. Своё решение описать в `docs/modules/agent.md`.
