# agent-01: системный промпт и схемы инструментов

**Исполнитель:** Давид

## Цель
Заменить тяжеловесный системный промпт (126 строк, 1025 токенов) на эталонный компактный промпт (13 строк, ~360 токенов), вынести детальные правила нормализации дат и времени в описания полей (`Field(description=...)`) Pydantic-схем с обязательным шаблоном-примером формата ISO 8601, и реализовать генератор опорного календарного контекста.

## Контекст
- **Стек:** Python 3.13, Pydantic v2 (по техническим решениям в `docs/decisions.md`).
- **Контрактная основа:** Контракт [`docs/contracts/agent-tools.md`](../contracts/agent-tools.md) и принятое решение об одном вызове LLM на реплику пользователя (`docs/decisions.md`).
- **Анализ текущей ветки `feature/agent_david-01-system-prompt`:**
  - В файле `backend/agent/system_prompt.py` системный промпт раздут до 1025 токенов.
  - Избыточные фрагменты, подлежащие удалению:
    1. Четырёхкратное дублирование времени: одновременно передаются `Сейчас: пятница, 24 октября...`, `Текущие дата и время в ISO 8601...`, `Сегодня: 2026-10-24`, `День недели: пятница`.
    2. Сезонные переводы часов: оговорка про сезонные сдвиги неактуальна для часовых поясов РФ.
    3. Защита от prompt injection: параноидальные оговорки занимают контекст и размывают внимание модели в прототипе ассистента.
    4. Инструкции второго хода: требования *«подтверждай действие после ответа тула»* и *«объясняй ошибки тулов»* противоречат нашему одношаговому циклу, где ответ формирует сервер, а не повторный вызов LLM.
- **Архитектурный принцип распределения инструкций:**
  Внимание трансформера (Self-Attention) при генерации аргументов инструмента максимально сконцентрировано на описании текущего поля JSON Schema. Поэтому правила нормализации полей («утром = 09:00», «до конца недели = вс 23:59:59», очистка от слов «напомни») должны находиться внутри параметров инструментов в Pydantic, а в системном промпте остаётся только глобальная роль и календарные якоря.
- **Обязательный строковый шаблон формата дат (ISO 8601):**
  Модели LLM без конкретного шаблона-примера часто путают часовые пояса (возвращают `Z` вместо локального пояса) или опускают время (`2026-10-25` вместо полной даты со временем), что ломает валидацию Pydantic `AwareDatetime`. Поэтому во всех описаниях дат и в системном промпте **обязательно указывается строковый пример**: `YYYY-MM-DDTHH:MM:SS+03:00` (например, `2026-10-25T15:00:00+03:00`).
- **Компактный системный промпт (`backend/agent/system_prompt.py`):**
  - Функция `build_compact_system_prompt(now: datetime, timezone_name: str) -> str`:
    - Вычисляет день недели на русском языке (понедельник ... воскресенье).
    - Вычисляет опорные даты: `сегодня` (YYYY-MM-DD), `завтра` (YYYY-MM-DD), `конец недели (воскресенье)` (YYYY-MM-DD).
    - Формирует компактный текст (не более 15 строк):
      ```
      Ты голосовой ассистент для задач, встреч и напоминаний.
      Помогай пользователю, вызывая ровно один подходящий инструмент на запрос.

      Контекст:
      - Текущее время: {now.isoformat(timespec="seconds")} ({weekday})
      - Часовой пояс: {timezone_name}
      - Опорные даты: сегодня {today_iso}, завтра {tomorrow_iso}, конец недели (вс) {end_of_week}

      Правила:
      1. Вызывай инструмент строго по схеме его параметров. Не придумывай данные и действия.
      2. Все даты и время возвращай в полном формате ISO 8601 со смещением пояса: YYYY-MM-DDTHH:MM:SS+03:00 (например: 2026-10-25T15:00:00+03:00).
      3. Относительные дни («завтра», «в пятницу») отсчитывай от контекста. «В пятницу», если сегодня пятница, означает следующую неделю.
      4. Если для встречи или задачи критически не хватает обязательных данных (нет времени встречи), вызывай инструмент ask_user. Не угадывай скрытые параметры.
      ```
- **Схемы 4 инструментов (`backend/agent/tools.py`):**
  - Перенеси в модуль `backend/agent/tools.py` классы Pydantic v2 строго по утверждённому контракту [`docs/contracts/agent-tools.md`](../contracts/agent-tools.md):
    - `CreateRecord`: поля `action`, `type`, `title`, `start`, `end`, `time_given`, `deadline`. В `description` полей `start`, `end`, `deadline` укажи строковый шаблон формата `YYYY-MM-DDTHH:MM:SS+03:00`, правила нормализации («утром» = 09:00, «в N» = N:00, «до конца недели» = воскресенье 23:59:59) и требование ставить `null`, если время не названо (НЕ 00:00!).
    - `ListRecords`: поля `action`, `date_from`, `date_to`, `types`. Чёткое описание в `description` класса: *«Показать список записей за явный календарный интервал ('что у меня сегодня', 'планы на неделю'). НЕ использовать для поиска по теме»*.
    - `SearchRecords`: поля `action`, `query`, `filters`. В `description` поля `query`: очистка от слов «найди», «поищи», «задачу про».
    - `AskUser`: поля `action`, `question`, `missing: list[str]`.
    - Дискриминированное объединение `LLMAction`.
  - Реализуй функцию `get_agent_tools() -> list[dict]`, которая экспортирует JSON Schema этих Pydantic-моделей в стандартный формат OpenAI Tools (`[{"type": "function", "function": {"name": ..., "description": ..., "parameters": ...}}]`).

### Источники для изучения
- **Явные строковые шаблоны форматов дат в параметрах схемы:** репозиторий [google-calendar-mcp](https://github.com/nspady/google-calendar-mcp/blob/main/src/tools/registry.ts) (файл `src/tools/registry.ts`, описания полей `start`, `end`, `timeZone`). Посмотри, как в описаниях аргументов явно прописан формат `YYYY-MM-DDTHH:MM:SS` с примерами — это удерживает внимание трансформера на правильной строке даже при лёгких моделях и устраняет галлюцинации таймзон.
- **Минималистичный системный промпт без дублей времени:** голосовой ассистент [Irene-Voice-Assistant](https://github.com/janvarev/Irene-Voice-Assistant/blob/master/plugins_inactive/plugin_ai_timer.py) (файл `plugins_inactive/plugin_ai_timer.py`). Пример того, как системный промпт сводится к 1–2 строкам роли, а все правила грамматики и чисел («полчаса = 30 минут») живут непосредственно в описании аргументов функции.

## Критерии готовности
- [ ] Размер сгенерированного системного промпта не превышает 400 токенов (замер через `tiktoken` / `cl100k_base`).
- [ ] Опорные даты (`сегодня`, `завтра`, `конец недели`) вычисляются корректно относительно переданного часового пояса.
- [ ] В `backend/agent/tools.py` объявлены все 4 класса действий со строгими типами Pydantic v2 по контракту `docs/contracts/agent-tools.md` с примерами формата `YYYY-MM-DDTHH:MM:SS+03:00`.
- [ ] Функция `get_agent_tools()` возвращает валидный список словарей инструментов для вызова через OpenAI API.
- [ ] Написано 2 быстрых смоук-теста через `pytest` на чистом Python:
  1. Тест генерации промпта (проверка наличия опорных дат и укладывания в лимит токенов).
  2. Тест парсинга валидного JSON в модель `CreateRecord` с проверкой парсинга смещения пояса.
