# Фронтенд

Страница ассистента: чат, панель «Мои дела», календарь, настройки LLM, голос. Постановки — [frontend-01](../tasks/archive/frontend-01-stranitsa-chata.md), [frontend-02](../tasks/archive/frontend-02-golos-na-stranitse.md), поля — только из [контрактов](../contracts/api.md).

## Стек
- **React + TypeScript**, сборка **Vite**, тесты **Vitest**. Библиотек дат и UI-китов нет: даты — встроенный `Intl`, вёрстка — свой CSS по макету.
- Почему так: интерфейс будет расти (чипы выбора, карточки изменений, календарь — product-04), React описывает экран через состояние, а не ручными правками DOM; TypeScript сверяет поля с контрактом при сборке — опечатка в имени поля не доходит до браузера.
- Образ для стенда собирает CI и публикует в GHCR (`docs/infra.md`): стадия `node:22-slim` ставит зависимости и собирает `dist/`, в итоговый образ `nginx:alpine` попадает только статика. `slim`, а не `alpine` — у сборщика и TypeScript 7 нативные бинарники.

## Как работает
- **Пользователь.** `X-User-Id` выдаёт сервер в ответ на первый запрос без заголовка. Клиент пускает без заголовка ровно один запрос, остальные ждут его ответа (`asUser` в `client.ts`) — иначе параллельные запросы панели и чата создали бы двух пользователей.
- **Восстановление.** 404 на чате — разговор не найден: забыть `conversation_id`, повторить один раз с `null`. 400 — испорченный `X-User-Id`: забыть, повторить без заголовка, показать «начат новый профиль»; параллельные запросы с тем же испорченным id начинают один профиль, а не несколько.
- **Ошибки.** Ошибки отправки пользовательской реплики выводятся карточкой прямо в ленте чата под репликой пользователя. Прочие системные ошибки (микрофон, сессия, сброс профиля, ошибки действий из панели) выводятся плашкой над полем ввода.
- **Ответ чата.** Отображается по макетам (постановка frontend-06): чистая функция `resolveResultView` (`lib/resultView.ts`) преобразует результат в карточки действий, списки или текст.
- **Даты.** Сервер присылает момент в UTC (чат) или со смещением (`/api/items`); всё переводится в пояс браузера через `Intl`. Правила показа — в `lib/dates.ts`, проверены тестами.
- **«Мои дела».** Лента из плитки «Без срока» и 5 дней с листанием стрелками «‹ ›» по 5 дней в прошлое и будущее. Один `GET /api/items` на 5 дней страницы: `from` — полночь первого дня, `to` — полночь шестого дня, со смещением пояса на каждую дату, `include_undated=true`. Перезапрос после каждого ответа чата и действий с записями сохраняет открытую страницу, не прыгая на «Сегодня». Вход и выход сбрасывают ленту на «Сегодня». Состояния оформлены по макету: скелетоны при загрузке, пустой день с иконкой и карточка ошибки с кнопкой «Повторить».

## Ответ ассистента и лента чата
Вся логика маппинга результатов ответа вынесена в чистую функцию `resolveResultView` (`src/lib/resultView.ts`) и покрыта тестами `resultView.test.ts`:

### Карточки действий под ответом
- **Создание (`create_record`):**
  - 1 запись: карточка с салатовым тегом `Задача создана` / `Встреча создана` / `Напоминание создано`, названием, временем (для задач без даты — подпись «без срока») и кнопками «Перенести», «Выполнено», «Удалить».
  - 2+ записи: единая карточка `Создано N записей` со списком созданных дел (название — когда).
- **Изменение (`update_record`):**
  - Единый фиолетовый тег `… изменена` (поскольку бэкенд не различает перенос времени и правку названия), новое время и кнопки действий. Если с изменением вернулось `restored` («не эту, а ту»), показывается только основная карточка изменения.
- **Статус (`set_status`):**
  - `done`: серый тег `✓ Выполнено`, зачёркнутое название, кнопка «↺ Не выполнено».
  - `cancelled`: серый тег `Отменено`, зачёркнутое название, подпись «Передумали? Скажите «верни»» и кнопка «↺ Вернуть».
  - `active`: фиолетовый тег `Возвращено`.
  - Массовые действия: единая карточка `Выполнено N записей` или `Отменено N записей`.
- **Откат (`undo_last`):**
  - Карточки с фиолетовым тегом `Возвращено` на каждую восстановленную запись из `restored`.
- **Пересечение встреч (`conflicts`):**
  - Рамка карточки подсвечивается акцентным оранжевым цветом (`--orange`), под чертой выводится блок «Пересекается с:» и строки с названиями и временем пересекающихся встреч.
- **Отказ и невыполнение (`ok = false`):**
  - Никаких карточек под ответом не рисуется — выводится только текст ответа ассистента.

### Нумерованный список и сворачивание
- В `list_records` и `search_records` номера отображаются в круглых фиолетовых бейджах `.list__num-badge`.
- Заголовки дней группируют записи: «Сегодня, 25 октября», «Завтра, 26 октября», «Среда, 28 октября».
- Если в списке больше 8 записей: по умолчанию показываются первые 8 записей и кнопка `⌄ Показать ещё N`. При разворачивании список открывается полностью с кнопкой `⌃ Свернуть`. Номера 1..N при развороте строго сохраняют исходный порядок.

### Ошибки в ленте чата
Ошибки отправки реплики пользователя отображаются карточками `.chat-error-card` на месте ответа ассистента:
- **`unknown` (нет связи, 5xx):** иконка перечёркнутого Wi-Fi, текст «Нет ответа от сервера. Не знаю, выполнено ли — проверьте «Мои дела».», кнопки «Открыть «Мои дела»» и «Отправить ещё раз».
- **`rejected` (4xx):** иконка `!`, текст «Сервер не принял запрос. Ничего не изменилось.», `detail` сервера и кнопка «Повторить».
- Карточки ошибок эфемерны: функция `saveChat` в `storage.ts` отфильтровывает сообщения `role === 'error'`, поэтому при перезагрузке страницы лента сохраняется без старых ошибок.

### Пустой экран чата
При пустой ленте сообщений (включая чистый старт и выход из аккаунта) отображается экран по макету: иконка микрофона в мягком фиолетовом круге, крупный заголовок «Чем помочь?», подзаголовок «Скажите или напишите — я запишу задачу, встречу или напоминание.» и 4 интерактивных чипа с подсказками запросов.


## Быстрые ответы (frontend-08)
В зависимости от значения `ChatResponse.awaiting` под текстом ответа ассистента выводятся интерактивные чипы быстрых ответов (`src/lib/quickReplies.ts`, `src/components/ResultView.tsx`):

| `awaiting` | Что отображается | Текст, отправляемый при клике |
|---|---|---|
| `choice` | Нумерованный список `result.candidates` и под ним чип на каждого кандидата (номер в кружке, название, время) | `номер N` (1..N в порядке candidates) |
| `confirm` | Нумерованный список `result.candidates` (со сворачиванием более 8 строк) и две кнопки: «Да, все» (акцентная) и «Отмена» | `да, все` / `отмена` |
| `time` | 4 чипа времени: «09:00 утром», «13:00 в обед», «15:00 днём», «18:00 вечером» | `в 09:00`, `в 13:00`, `в 15:00`, `в 18:00` |
| `answer`, `null` | Быстрые ответы не отображаются | — |

- **Когда чипы активны:** только у последнего ответа ассистента в ленте и пока не идёт отправка (`!pending`).
- **После ответа:** если пользователь нажал чип, он сохраняется в сообщении (`selectedChip`), выделяется фиолетовым фоном, а остальные чипы затухают. Если пользователь ответил текстом или голосом — все чипы отображаются затухшими (по макету «Чат · выбор · после ответа»).
- **Ошибки сети/сервера:** при ошибке отправки выбранный чип сбрасывается, и кнопки остаются активными, позволяя нажать повторно.

## Настройки (frontend-09, product-06)
Окно настроек (`SettingsModal.tsx`) выполнено по новым макетам с вкладками (`Общие`, `Напоминания`, `Модель`, `Google`):
- **Вкладка «Общие»:**
  - **Часовой пояс:** выбор часового пояса (`lib/timezones.ts`). По умолчанию выбран режим «Как в браузере». Выпадающий список с поиском, быстрым списком популярных городов России (Москва, Екатеринбург, Новосибирск, Владивосток и др.) и зарубежных поясов. При смене пояса все запросы к API (`/api/items?tz=...`, `/api/chat`) и отображение времени в календаре и делах переключаются на выбранный пояс.
  - **Бейдж пояса в «Моих делах»:** если выбран пояс, отличный от часового пояса браузера, в шапке панели «Мои дела» отображается бейдж с иконкой глобуса, названием города и смещением UTC (например, `Екатеринбург · UTC+5`).
  - **Озвучка ответов:** тумблер включения/выключения голосовой озвучки ассистента («Озвучивать ответы голосом»).
- **Вкладка «Напоминания»:**

  - Ссылка на страницу политики конфиденциальности (`privacy.html`).

## Тема оформления
- По умолчанию тема соответствует системным настройкам (`prefers-color-scheme`).
- Кнопка-иконка в шапке (слева от календаря) переключает тему на противоположную (в светлой теме отображается луна, в тёмной — солнце) и запоминает выбор в `localStorage` (`gorky.theme`).
- Вёрстка в `styles.css` применяет тёмные переменные как по `@media (prefers-color-scheme: dark)` (если тема системная), так и по селектору `:root[data-theme="dark"]`. Переменные тёмной темы определены в одном месте, исключая расхождения.
- В `index.html` встроен синхронный скрипт в `<head>`, читающий `gorky.theme` и выставляющий атрибут `data-theme` до первого рендера, предотвращая вспышку светлой темы при загрузке.

- **Режимы отображения:** сегментированный переключатель «День», «Неделя», «Месяц».

Дела распределяются по часам, клик по карточке открывает окно «Детали записи», клик по пустому слоту — создание записи на выбранный час. ## Голос
Голос — обёртка над текстовым чатом: запись → `POST /api/stt` → текст в ленту → тот же код отправки, что у набранной реплики.
- **Кнопка микрофона** — только если браузер умеет записывать (`MediaRecorder` и `getUserMedia`; микрофон доступен по HTTPS или на localhost). Нажал — идёт запись («Идёт запись звука» с уровнем громкости), нажал ещё раз — запись уходит на распознавание. На 30-й секунде запись останавливается и уходит сама: длиннее сервер не принимает.
- **Формат** — первый, который поддерживает браузер: `audio/webm` (Chrome, Android), `audio/mp4` (Safari, iOS), `audio/ogg`. Файл уходит как есть, тип — без параметров кодека.
- **Ошибки.** Нет доступа к микрофону, микрофона нет, микрофон занят — сообщение, что сделать. Ошибка распознавания (413, 415, 422, 429, 503) — `detail` сервера. В этих случаях в чат ничего не уходит.
- **Ожидание распознавания** показывается тем же «Ассистент думает…» — отдельного «Распознаю» в макете нет.
- **Озвучка** — каждый ответ ассистента, и на голос, и на текст: `reply` как есть, голос `ru-RU` браузера (локальный — предпочтительнее). Список голосов приходит не сразу — ждём `voiceschanged` до 1,5 с. Русского голоса нет — не озвучиваем и один раз за открытие страницы говорим, что озвучка недоступна. Новая запись или реплика обрывает текущую озвучку.

Проверено (2026-10-26): Chrome на Windows — русские голоса есть (Microsoft Irina, Pavel), озвучка идёт и обрывается; отказ в доступе к микрофону даёт сообщение. Не проверено: запись и распознавание целиком — `/api/stt` ещё нет на стенде (voice-01); телефоны (iOS, Android) — наличие русского голоса и запись.

## Действия с записями
Всё, что ассистент делает голосом, можно выполнить вручную без участия LLM:
- **Эндпоинты:**
  - `POST /api/items?tz=<tz>` (`CreateItem`) → 201 `ActionResult`;
  - `PATCH /api/items/{id}?tz=<tz>` (`UpdateItem`) → 200 `ActionResult`;
  - `POST /api/items/{id}/status?tz=<tz>` (`SetItemStatus`) → 200 `ActionResult`.
  Все запросы отправляются с учётом авторизации: токен для авторизованных, `X-User-Id` для гостя.
- **Окно записи (`RecordDialog.tsx`):**
  - Создание: тип (задача, встреча, напоминание), название, день, время, «весь день», дедлайн. При открытии из календаря день подставляется автоматически.
  - Редактирование: изменение названия, перенос дня и времени, смена статуса («выполнено» / «не выполнено»), удаление. При переносе встречи `end` не отправляется — сервер рассчитывает конец автоматически с сохранением длительности.
  - Предупреждение о конфликтах: при наличии `conflicts` окно предупреждает о пересечении встреч перед закрытием.
- **Мягкое удаление и откат (`Toast.tsx`):**
  - При удалении выставляется статус `cancelled`, запись скрывается из списков, внизу страницы всплывает плашка «Удалено · Вернуть» на 8 секунд.
  - Клик «Вернуть» восстанавливает запись в статус `active`.
- **Обновление состояния:**
  - Перезапрашиваются «Мои дела» (`panel.load()`) и календарь (`reloadKey`).
  - В ленте чата запись обновляется на месте без изменения порядка и нумерации строк (чтобы голосовые реплики вроде «перенеси вторую» продолжали указывать на правильные записи).

## Учётки и вход
Вход и регистрация по желанию: гость сразу работает с ассистентом без авторизации.
- **Хранение.** `gorky.auth` в `localStorage` хранит `{ token, account }` (`AuthResponse`). Гостевой идентификатор `gorky.userId` не удаляется при входе: при выходе пользователь возвращается к своим записям гостя.
- **Заголовки.** Если выполнен вход — каждый запрос к `/api/*` уходит с заголовком `Authorization: Bearer <token>` и без `X-User-Id`. Без входа запросы уходят с `X-User-Id`, как раньше.
- **Истечение сессии (401).** 401 на запрос с токеном означает, что токен недействителен или просрочен. Клиент очищает локальный вход (`auth = null`, `saveAuth(null)`), оповещает подписчиков `onSessionExpired`, не повторяет запрос гостем и показывает уведомление «Сессия входа истекла — вы снова гость. Войдите ещё раз.». 401 на `login` («неверный логин или пароль») подписчиков не вызывает и возвращает ошибку с `detail`.
- **Смена пользователя (`switchUser`).** При входе, регистрации, выходе или истечении сессии:
  - сбрасывается лента сообщений (`conversationId: null, messages: []`), так как старый `conversation_id` вернёт 404 у другого пользователя;
  - останавливается активная озвучка (`stopSpeaking`) и голосовая запись;
  - перезапрашиваются «Мои дела» (`panel.load()`);
  - календарь пересоздаётся через смену ключа `<CalendarView key={account?.id ?? 'guest'} />` и загружает записи нового пользователя.
- **Выход (`logout`).** Запрос `POST /api/auth/logout` отправляется с токеном. Локально вход сбрасывается в любом случае — и при статусе 204, и при сетевом сбое.

## Состояние в браузере (localStorage)
| Ключ | Что |
|---|---|
| `gorky.userId` | `X-User-Id` (гость) |
| `gorky.auth` | сохранённый вход `{ token, account }` |
| `gorky.chat` | `conversation_id` и сообщения ленты этого разговора (эндпоинта истории нет). Не влезает — отбрасываются самые старые сообщения |
| `gorky.llm` | настройки LLM; все поля пусты — ключ удаляется |
| `gorky.theme` | выбранная тема (`light` или `dark`, нет ключа — системная) |
| `gorky.tz` | выбранный IANA часовой пояс (`null` — пояс браузера) |
| `gorky.voice_output` | флаг голосовой озвучки ответов (`true` / `false`) |
| `gorky.reminders` | настройки напоминаний `{ enabled: boolean, leadMinutes: number }` |

Без localStorage (приватный режим, запрет сайта) страница работает, но ничего не переживает перезагрузку.

## Запуск
```bash
cd frontend
npm ci
npm run dev                                  # http://localhost:5173, /api → локальный бэкенд :8000
API_TARGET=https://gorky.bond npm run dev    # /api → стенд
npm test                                     # тесты дат, формы, настроек, темы и клиента
npm run build                                # проверка типов и сборка в dist/
```
Образ: `docker compose build frontend` (для стенда его так же собирает CI, см. `docs/infra.md`).

CI запускает `npm ci`, `npm test` и `npm run build` на каждый PR (`docs/infra.md`, «Что проверяет CI»); перед PR полезно прогнать их локально.
