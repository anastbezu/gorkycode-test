# Фронтенд

Страница ассистента: чат, панель «Мои дела», настройки LLM. Постановка — [frontend-01](../tasks/frontend-01-stranitsa-chata.md), поля — только из [контрактов](../contracts/api.md).

## Стек
- **React + TypeScript**, сборка **Vite**, тесты **Vitest**. Библиотек дат и UI-китов нет: даты — встроенный `Intl`, вёрстка — свой CSS по макету.
- Почему так: интерфейс будет расти (чипы выбора, карточки изменений, календарь — product-04), React описывает экран через состояние, а не ручными правками DOM; TypeScript сверяет поля с контрактом при сборке — опечатка в имени поля не доходит до браузера.
- Образ собирается на сервере при деплое: стадия `node:22-slim` ставит зависимости и собирает `dist/`, в итоговый образ `nginx:alpine` попадает только статика. `slim`, а не `alpine` — у сборщика и TypeScript 7 нативные бинарники.

## Структура
```
frontend/
  index.html            точка входа Vite
  nginx.conf            отдача статики: /assets/* — кэш на год (имена с хешем), index.html — без кэша
  Dockerfile            сборка → nginx
  vite.config.ts        dev-сервер, прокси /api
  src/
    main.tsx            запуск React
    App.tsx             страница: лента, отправка, ошибки, панель, настройки
    api/types.ts        типы из контрактов (Record, ActionResult, ChatRequest/Response, LLMConfig)
    api/client.ts       запросы, X-User-Id, восстановление после 400/404, виды ошибок
    lib/dates.ts        показ дат словами в поясе браузера, границы суток для /api/items
    lib/storage.ts      состояние в localStorage
    components/         ResultView (карточки и нумерованный список), TasksPanel, SettingsModal, icons
    styles.css          палитра и вёрстка по макету, светлая и тёмная тема
```

## Как работает
- **Пользователь.** `X-User-Id` выдаёт сервер в ответ на первый запрос без заголовка. Клиент пускает без заголовка ровно один запрос, остальные ждут его ответа (`asUser` в `client.ts`) — иначе параллельные запросы панели и чата создали бы двух пользователей.
- **Восстановление.** 404 на чате — разговор не найден: забыть `conversation_id`, повторить один раз с `null`. 400 — испорченный `X-User-Id`: забыть, повторить без заголовка, показать «начат новый профиль»; параллельные запросы с тем же испорченным id начинают один профиль, а не несколько.
- **Ошибки двух видов.** «Результат неизвестен» — сеть, таймаут (чат — 60 с), 5xx, HTML от nginx: сервер мог успеть выполнить, плашка с «Повторить» (перед повтором перезапрашивается панель). «Сервер не принял» — 4xx с `detail` (строка или список ошибок валидации): ничего не сделано, повторять бессмысленно.
- **Ответ чата.** `reply` — как есть. `create_record` — карточка на каждую запись; `list_records`/`search_records` — нумерованный список в полученном порядке, заголовки дней — если дни разные. Остальное (непустые `candidates`, `conflicts`, `restored`, `missing`, `awaiting`, другие действия) — только `reply`.
- **Даты.** Сервер присылает момент в UTC (чат) или со смещением (`/api/items`); всё переводится в пояс браузера через `Intl`. Правила показа — в `lib/dates.ts`, проверены тестами.
- **«Мои дела».** Один `GET /api/items` на 7 дней: `from` — сегодня 00:00, `to` — 00:00 восьмого дня, со смещением пояса на каждую дату, `include_undated=true`. Перезапрос — после каждого ответа чата 200. Ответ более раннего запроса, пришедший позже, не затирает свежие данные.

## Состояние в браузере (localStorage)
| Ключ | Что |
|---|---|
| `gorky.userId` | `X-User-Id` |
| `gorky.chat` | `conversation_id` и сообщения ленты этого разговора (эндпоинта истории нет). Не влезает — отбрасываются самые старые сообщения |
| `gorky.llm` | настройки LLM; все поля пусты — ключ удаляется |

Без localStorage (приватный режим, запрет сайта) страница работает, но ничего не переживает перезагрузку.

## Запуск
```bash
cd frontend
npm ci
npm run dev                                  # http://localhost:5173, /api → локальный бэкенд :8000
API_TARGET=https://gorky.bond npm run dev    # /api → стенд
npm test                                     # тесты дат и клиента
npm run build                                # проверка типов и сборка в dist/
```
Образ: `docker compose build frontend` (то же делает деплой на сервере).

Тесты в CI не запускаются (CI — ruff и pytest бэкенда); перед PR — `npm test` и `npm run build` локально.
