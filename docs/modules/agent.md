# Агент

## Подготовка запроса

`process_user_turn` получает IANA-пояс браузера из `ChatRequest.timezone`,
создаёт один aware `now` в этом поясе и использует его на весь запрос:

```python
now = now.astimezone(zone) if now is not None else datetime.now(zone)
prompt = build_compact_system_prompt(now, timezone_name)
tools = localize_tools(get_agent_tools(), now)
result = await execute(db, user_id, action, now=now)
```

Необязательный именованный параметр `now` подставляют автотесты (agent-08: «сейчас» —
среда 21.10.2026 10:00 по `Europe/Moscow`); без него берётся текущее время, как раньше.
Тот же `now` уходит в модель, в описания инструментов и в сервис `create_record`:
проверка «дата в прошлом» считает от того же момента, что и модель.

`build_compact_system_prompt` находится в `agent/system_prompt.py`,
`get_agent_tools` и `localize_tools` — в `agent/tools.py`.

Базовый промпт содержит 15 строк: роль, один инструмент, время, пояс,
даты всех дней двух недель и общие правила. Отсчёт недель выполняется
после перевода времени в пояс пользователя, начало недели — понедельник.
Модель не получает инструкции о втором ходе после исполнения инструмента.

## Схемы и локализация

Единый источник моделей — `backend/schemas/actions.py`.
`get_agent_tools()` экспортирует CreateRecord, ListRecords, SearchRecords,
AskUser и Help в формат OpenAI Chat Completions Tools. `$defs` и `$ref` сохраняются.
Модели импортируются из `schemas`, копий Pydantic-моделей в агенте нет.

Описания дат в исходных `Field(description=...)` должны содержать
`{ISO_EXAMPLE}`. `localize_tools(tools, now)` делает глубокую копию и заменяет
этот маркер только в строках `description`, включая вложенные `$defs`.
Используется `str.replace`, остальные фигурные скобки не интерпретируются.
Пример — 15:00 локальной даты `now` с вычисленным смещением её пояса.
Базовые схемы и результаты других запросов не изменяются.

## Дата без явно названного времени

Согласованная интерпретация: если назван день, `start` содержит локальное
начало этого дня и `time_given=false`. Это техническое представление даты,
а не заявленное пользователем время. Для задачи сервис выставляет all_day.
`start=null` означает, что дата вообще не названа.
Для встречи без времени сервис возвращает `missing=["start"]`, агент
уточняет время. При известных `type` и `title` модель возвращает `CreateRecord`
даже без времени: так название и дата попадут в черновик. Если обязательные
`type` или `title` неизвестны, доступен `ask_user`.
Срок «до конца недели» хранится в deadline: воскресенье 23:59:59.
Сигнал all_day формирует сервис, в CreateRecord нового поля нет.

## Исполнение и ответ

Один вызов LLM выбирает действие. Код исполняет его, проверяет результат и
формирует ответ по шаблонам ActionResult: успех, ошибка, отсутствие результатов,
missing и выбор кандидата. Обработчик missing сохраняет pending-состояние.
Второй вызов LLM в рамках той же реплики не требуется.
Вызов SDK, исполнение и хранение состояния реализует владелец каркаса агента.

## Клиент LLM

`agent/llm.py::make_client(llm_config)` создаёт `AsyncOpenAI` и возвращает
его вместе с именем модели. Каждое поле берётся из `LLMConfig` запроса,
а если там пусто — из окружения: `base_url` ← `LLM_BASE_URL`,
`api_key` ← `LLM_API_KEY`, `model` ← `LLM_MODEL`. Условий на конкретного
провайдера в коде нет. Пустой `LLM_BASE_URL` означает адрес OpenAI
по умолчанию. Таймаут — 15 секунд, один повтор.
Нет ключа или модели — `LLMConfigError`.

## Вызов и разбор действия

`get_action(text, now, timezone_name, llm_config, *, context="")` делает один вызов
`chat.completions.create`: системный промпт с компактным контекстом и текущая пользовательская фраза,
пять локализованных инструментов, `tool_choice="required"`.
Принимается ровно один tool call; имя инструмента и JSON-аргументы проверяются
через `LLMAction.model_validate({**args, "action": name})`. Нет вызова
инструмента, битый JSON, неопубликованный инструмент или поля не проходят схему — `ActionParseError`.

## Реестр действий

`agent/actions.py::ACTIONS` сопоставляет `action` с обработчиком
`(db, user_id, action, now=None) -> ActionResult`; `execute` выбирает обработчик по
`action.action`, для неизвестного действия возвращает `ok=False` с ошибкой.
`ask_user` в реестр не входит: `process_user_turn` сохраняет ожидание и возвращает
`AskUser.question` с `awaiting="answer"`, не заменяя существующий черновик вопросом.

`create_record` вызывает настоящий `services.records.create_record` через `asyncio.to_thread`:
успешная запись сохраняется в PostgreSQL, встреча без времени возвращает `missing=["start"]`.
`list_records` вызывает настоящий `list_records_for_period`, `search_records` —
`services.search_stub.search_by_substring`; оба вызова также идут через `asyncio.to_thread`.
Результат передаётся в `reply_for_result` вместе с исходным действием и `now`, чтобы сохранить
короткие голосовые ответы agent-04. `ListRecords.date_to=None` поддерживается: верхней границы
нет, в конец выдачи добавляются активные записи без даты; ответ начинается с «Начиная с …».

Для приветствий, справки и посторонних реплик опубликован уже согласованный `Help`.
Его обработчик не обращается к записям, ответ строится шаблоном и не начинает уточнение.
Это заменяет прежний обход через `AskUser`: `tool_choice="required"` больше не вынуждает
модель выбирать список дел для «Привет».

## Черновик и фокус разговора (agent-03)

Каждый ход загружает `ConversationState` через `get_or_create_conversation_state`.
Хранилище проверяет владельца разговора; `ConversationAccessError` передаётся вызывающему API.
В LLM отправляются только два сообщения: system с актуальными инструкциями и строками
состояния, user с новой репликой. Предыдущие реплики, настройки LLM и ключ API в черновик не входят.

`agent/context.py::build_draft_context(state)` сериализует `pending`, `missing`, `awaiting`
в одну строку JSON внутри `[Черновик: ...]`. Кавычки и переводы строк экранируются;
данные черновика и фокуса не считаются инструкциями для модели.

Поток создания встречи:

1. «Поставь встречу с Денисом» → LLM возвращает `CreateRecord` с названием и `time_given=false`.
2. Сервис сообщает `missing=["start"]`. Агент сохраняет `pending=LLMAction(action)`,
   `missing`, `awaiting="answer"`, очищает `candidates` и формирует `AskUser` шаблоном в коде.
3. «В 15:00» → LLM получает строку черновика и возвращает полный `CreateRecord`.
   Отдельный patch только с `start` не проходит контракт `LLMAction`.
4. Агент дописывает через `merge_pending` только ожидаемые поля дат; для `start` также
   `time_given`. Название, тип и остальные значения сохраняются из черновика.
5. Сервис повторно проверяет действие. Даже если `start` уже не `None`, дата без времени
   требует уточнения; `missing` из сервиса имеет приоритет над результатом `merge_pending`.
6. При успехе агент вызывает `clear_pending`, сбрасывает `candidates`, записывает
   ID созданной записи в `focus_record_id` и сохраняет состояние.

Время без даты относится к дате черновика, а без неё — к сегодняшней дате в поясе пользователя.
Прошлое время отклоняет сервис; автоматического переноса на завтра нет. Ответ с одной датой
дополняет черновик, но оставляет ожидание времени, поэтому возможны три и более шага.
При ошибке LLM черновик не меняется. При ошибке сервиса дополненный черновик и ожидание
сохраняются для исправления. `AskUser` не стирает уже собранные параметры.
Независимый список/поиск не очищает незавершённое создание. Создание другого типа сбрасывает
старый черновик; оно не сливается с названием старой встречи. При создании того же типа
агент продолжает текущий черновик. Полный жизненный цикл смены темы — отдельная задача agent-06.

При единственной записи в успешном результате создания, списка или поиска обновляется фокус.
Пустой или множественный результат этих действий снимает фокус согласно свежему контракту.
На следующем ходе `services.records.get_record`
загружает запись с проверкой `user_id`; `build_focus_context` добавляет название,
начало в поясе пользователя и `all_day`. Недоступный/удалённый фокус очищается.
UUID в строку фокуса не попадает: идентификаторы остаются на сервере.

Все обращения к БД выполняются последовательно через `asyncio.to_thread`, без одновременного
использования одной сессии. Формирование контекста и слияние — чистые операции без БД.

Ограничения этой версии:

- TTL не вводится. `updated_at` есть только в ORM, но не в публичной `ConversationState`.
- Схемы `UpdateRecord`, `SetStatus`, `UndoLast` уже появились в `LLMAction`, но их обработчики
  ещё не реализованы и эти инструменты не экспортируются. Множественные tool calls,
  изменение/статус/откат — agent-07; `shown`, `last_action`, `pending_skipped`, отказы
  и расширенный контекст — agent-06 после поддержки хранения в backend-03.
- Черновик создания требует известных `type` и `title`. `AskUser` без черновика сохраняет
  ожидание, но не частичные аргументы: для универсального сбора обязательных полей нужен
  согласованный контракт. Новые поля схем не добавляются; уточнено только описание даты без времени,
  с сохранением новых умолчаний времени из `develop` («в 3» = 15:00 и части дня).
- `create_record` и `save_conversation_state` делают отдельные commit. Если запись создана,
  а сохранение состояния упало, в БД может остаться старый черновик; повтор способен создать
  дубликат. Атомарность/идемпотентность и сериализацию одновременных ходов одного разговора
  переход к одной транзакции предусмотрен backend-03. Ошибка сохранения состояния не маскируется
  подтверждением. Пока backend-03 не реализован, сервисы продолжают коммитить сами.
- `/api/chat` вызывает `process_user_turn` (agent-05), временный диспетчер
  `handle_without_llm` удалён.

## Ошибки

`process_user_turn` не пробрасывает ошибки LLM наружу, пользователь
получает `ChatResponse` с понятным `reply` и `result=None`:

| Ошибка | Ответ |
|---|---|
| `LLMConfigError` — нет ключа или модели | ассистент не настроен, задать ключ и модель |
| `openai.APIError` — таймаут, сеть, лимиты, 5xx | сервис распознавания временно недоступен |
| `ActionParseError` | не удалось разобрать запрос |

## Шаблоны ответа

`agent/replies.py` строит `reply` из `ActionResult` без второго вызова LLM:
`missing` → вопрос о недостающем поле (`awaiting="answer"`), ошибка →
`error`, созданная запись → «Готово: «название» на дд.мм в чч:мм» во времени
пользователя.

Текст ответа на список и поиск тоже пишет шаблон в коде, а не LLM: один вызов
LLM на реплику, второго хода нет. `reply` — короткий вариант для озвучки,
полный список интерфейс берёт из `result.records`.

- `agent/list_replies.py::reply_for_list` — список за период: «На завтра 2 дела:
  …», вслух не больше трёх пунктов, дальше «Остальные на экране». Даты словами
  («завтра», «в пятницу», «13 ноября»), время в 24-часовом формате. Запись на
  весь день (`all_day`) и задача только со сроком называются без времени.
- `agent/search_replies.py::reply_for_search` — поиск: одна запись — название и
  когда; несколько — количество и ближайшая будущая запись, а если будущих нет — последняя
  прошедшая (не первая в выдаче: поиск может сортировать по похожести); ничего — «По запросу «…» ничего не
  нашлось». Вопроса «Поискать шире?» нет: без состояния диалога ответ «да» не
  к чему привязать.
- «Уже прошло» для сегодняшнего дня не реализовано: решение в ASSISTANT_TEXTS
  не подтверждено.

## Поиск

До модуля Родиона действует заглушка `services/search_stub.py`: название записи
должно содержать каждое слово запроса длиннее двух букв (`ILIKE`, спецсимволы
экранированы). Фильтры из `SearchFilters` применяются как в контракте; без
фильтра по статусу скрыты только отменённые. Сортировка — от новых к старым,
`score` у всех 1.0. Аргумент `db` первым соответствует обновлённому контракту поиска.
Подмена на `search()` — в
`agent/actions.py::handle_search_records`.

## Фокус разговора

`process_user_turn` использует чистую функцию `agent/focus.py::focus_record_id(result)`
внутри общего сохранения состояния. После действия состояние сохраняется один раз.
Прежняя отдельная запись фокуса (`remember_focus`) удалена в agent-05.
Справка и ошибка не меняют существующий фокус.

## Подключение к `/api/chat` (agent-05)

Маршрут `api/chat.py` проверяет пояс (`parse_timezone`), владельца разговора (чужой или
несуществующий `conversation_id` — 404), загружает стартовый датасет новому пользователю и
вызывает `process_user_turn(db, user.id, conversation_id, req.text, zone.key, req.llm_config)`.
В агента идёт уже проверенный пояс `zone.key`.

- **Сессия БД** приходит в маршрут через `Depends(get_session)` и передаётся агенту аргументом
  `db`. Агент сессию не открывает и не закрывает.
- **Обёртка в поток** — в местах вызова: обработчики `agent/actions.py` и загрузка/сохранение
  состояния в `agent/agent.py` вызывают синхронные сервисы через `asyncio.to_thread`,
  последовательно, без одновременного использования одной сессии.
- **Транзакции.** Агент не коммитит. Пока сервисы `create_record` и
  `save_conversation_state` коммитят сами — это две транзакции на реплику (последствия описаны
  в ограничениях выше). После backend-03 сервисы перестают коммитить, коммит один — в маршруте.
- **Ответ** на создание подтверждает дату и время во времени пользователя; задача на весь день
  называется без «00:00». Ошибки бизнес-правил («дата в прошлом») приходят текстом, без 500.
