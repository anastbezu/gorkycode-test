# Агент

## Подготовка запроса

`process_user_turn` получает IANA-пояс из `ChatRequest.timezone`, создаёт один aware
`now` и использует его для календаря, локализации инструментов и ответа.
`build_compact_system_prompt` находится в `agent/system_prompt.py`,
`get_agent_tools` и `localize_tools` — в `agent/tools.py`.

Промпт содержит 15 строк: роль, время, пояс, календарь двух недель и общие правила.
Начало недели — понедельник. Даты и границы периодов описаны преимущественно в полях
`backend/schemas/actions.py`. `localize_tools` глубоко копирует схемы и заменяет
`{ISO_EXAMPLE}` только в `description`, включая вложенные `$defs`.
Базовые схемы и результаты других запросов не меняются.

`get_action` отправляет ровно два сообщения: system с актуальным состоянием и user
с текущей репликой. История сообщений не отправляется. Один вызов
`chat.completions.create`, `tool_choice="required"`, ровно один tool call.
Имя и JSON-аргументы проверяются через `LLMAction.model_validate`.
Пустой/неизвестный вызов или нарушение схемы — `ActionParseError`.

## Порядок обработки реплики (agent-06)

1. Загрузить состояние с проверкой владельца разговора.
2. Если есть ожидание и вся нормализованная реплика совпадает с фразой отказа,
   очистить черновик, признак пропуска, кандидатов и ожидание. Сохранить один раз,
   ответить «Хорошо, не ставлю» / «Хорошо, ничего не меняю». LLM не вызывается.
3. Последовательно загрузить доступные записи из `shown[:10]`, фокуса и первых трёх
   записей последнего действия. Повторяющиеся ID читаются один раз, всегда с `user_id`.
   Недоступный фокус снимается; пропуски в показанном списке сохраняют свои номера.
4. Собрать компактный контекст и вызвать модель.
5. Ответ на уточнение создания дополняет только ожидаемые поля дат; для `start`
   также `time_given`. Название, тип и остальные заполненные значения сохраняются.
   Слияние непустых значений выполняет `merge_pending`; полноту проверяет сервис.
6. Исполнить действие через `execute` (`ask_user` обрабатывается без сервиса).
7. Вызвать `update_state`, сохранить состояние один раз и сформировать ответ шаблоном.
   При первом отвлечении от черновика добавить напоминание о незавершённом действии.

Фразы отказа: «не надо», «забудь», «отмена», «проехали», «забей», «неважно»,
«отбой», «стоп». Нормализация: NFKC, регистр, пунктуация и пробелы.
Сверяется вся фраза: «Отмени встречу с Иваном» и «не надо отменять» не являются отказом.

## Интерфейс для agent-07

Общий переход состояния — в `backend/agent/state.py`:

```python
from agent.state import update_state

state = update_state(state, action, result, before=before)
```

Сигнатура: `update_state(state, action, result, *, before=None) -> ConversationState`.

- `action` — конкретная модель действия; обёртка `LLMAction` также принимается.
- `result` — `ActionResult`; только для `AskUser` можно передать `None`.
- `before` — список словарей с прежними значениями записей ДО изменения/смены статуса,
  в порядке `result.records`. Функция делает глубокую копию. Создание всегда хранит
  `before=[]`; при нескольких созданиях `record_ids` содержит все созданные записи.
- Функция чистая: возвращает новое состояние, не меняет входы, не вызывает БД и не коммитит.
  Вызывающий присваивает результат и сохраняет его один раз после исполнения.
- Кандидаты переводят состояние в `choice`, записывают `pending`, `candidates` и
  `shown` в исходном порядке, без группировки. Успешный выбор очищает ожидание
  и заменяет `shown` выбранными записями.
- Успешные создание, изменение и статус обновляют `last_action`. Список, поиск,
  справка, вопросы и ошибки его сохраняют. Откат очищает `last_action`;
  непустой `restored` тоже очищает прежнее действие, даже если новая цель неоднозначна.
- Фокус ставится на единственную созданную/изменённую/показанную запись,
  снимается при пустом или множественном результате. При откате используется `restored`.
- `agent/focus.py` оставлен только как совместимый импорт `focus_record_id`.
  Отдельного сохранения через `remember_focus` и подавления ошибок БД больше нет.

Обработчики изменения, статуса, отката, разрешение цели и несколько tool calls остаются
в agent-07. Он передаёт `before` в общий переход; агент не записывает эти поля в обход него.

## Контекст и порядок записей

`build_state_context(state, records, timezone_name)` в `agent/context.py` принимает
уже загруженные записи и возвращает не больше четырёх строк:

- `Показано:` — до 10 записей под номерами; название, тип, дата/время в поясе пользователя,
  «весь день», срок или «без даты». Выполненные и отменённые помечаются.
- `В фокусе:` — одна запись.
- `Последнее действие:` — действие и названия/даты затронутых записей.
- `Черновик:` — компактный JSON действия, `missing` и `awaiting`.
  Если частичного действия нет, передаётся только ожидание уточнения.

Пустое состояние даёт пустую строку. UUID, `before`, история сообщений и настройки LLM
в контекст не входят. Кавычки и переводы строк экранируются; данные не являются
инструкциями. Недоступные/чужие записи пропускаются. Номера не уплотняются:
если запись 1 удалена, запись 2 остаётся номером 2, соответствующим `shown[1]`.
Промпт связывает «вторую» с `target.index`, «её/эту» и поправку — с `target.focus`.

`agent/presentation.py::group_records` — общий источник групп для ответа и `shown`.
Одинаковые название, тип и статус группируются в порядке первого появления.
Представитель — последняя по дате запись (`start`, иначе `deadline`, иначе `created_at`).
Пример: «Созвон — 7 раз, последний 22.08.2026». Разные типы/статусы не склеиваются.
`shown_records` возвращает представителей первых 10 групп.
Шаблоны списка и поиска используют те же группы и номера; вслух — максимум три группы.
Полная исходная выдача остаётся в `ActionResult.records`. Кандидаты не группируются.

## Черновик и смена темы

Продолжение черновика создания — `create_record` того же типа или `ask_user`.
Первый самостоятельный запрос выполняется, оставляет черновик и выставляет
`pending_skipped=True`; ответ напоминает о нём. Второй подряд самостоятельный запрос
сбрасывает черновик. Создание другого типа сбрасывает его сразу.
Ответ по черновику снимает `pending_skipped`, затем идёт обычное слияние и проверка сервиса.

Поэтому «встреча завтра» → «что у меня завтра?» → «в 16» завершает встречу,
а после двух посторонних запросов «в 16» уже не имеет черновика для продолжения.
Ошибка LLM не меняет сохранённый черновик. Ошибка сервиса при продолжении сохраняет
уточнённые данные и ожидание. Ошибка сохранения состояния пробрасывается:
подтверждение успешного сохранения вместо неё не выдаётся.

## Даты и время

Дата без времени — локальные 00:00 и `time_given=false`; `start=null` — даты нет.
Для встречи без времени сервис возвращает `missing=["start"]`, даже если дата уже есть.
Время без даты пока относится к дате черновика, иначе — к сегодня.
Прошлое время не переносится на завтра.

Описания полей задают:

- Период списка — `[date_from, date_to)`. Для целых дней конец — 00:00 дня после
  последнего дня периода, не 23:59. «На неделю» — с текущего понедельника;
  «на следующей неделе» — со следующего; выходные — суббота–понедельник.
- «До конца недели» в списке — сегодня 00:00 до следующего понедельника 00:00.
  Без периода начало — сегодня 00:00, конец — `null`.
- «Сегодня вечером» в списке — 18:00 до завтра 00:00.
  `deadline` «до конца недели» остаётся воскресеньем 23:59:59.
- При создании «следующий <день недели>» — день следующей календарной недели;
  «на выходных» — суббота; «в конце месяца» — последний день.
- Общее правило промпта: день недели, совпадающий с сегодняшним, — через семь дней.
  Явное «сегодня» или конкретная дата имеют приоритет.

`SearchFilters` использует такие же границы целых дней, но неназванные границы
остаются `null`. Смещение вычисляется для даты в поясе пользователя.

## Хранение и интеграция

Миграция `0003_conversation_context` добавляет уже согласованные поля
`shown`, `last_action`, `pending_skipped` в ORM и PostgreSQL.
`services.conversation` сохраняет и загружает их вместе с остальным состоянием.
Перед запуском обновлённого агента: `uv run alembic upgrade head`.

Агент не вызывает commit. В текущей ветке сервисы ещё коммитят сами;
единая транзакция на реплику остаётся работой backend-03. При объединении его ветки
нужно согласовать миграцию этих трёх колонок, чтобы не добавить их повторно.
Атомарность создания записи и сохранения состояния здесь ещё не обеспечена.

`/api/chat` пока использует `handle_without_llm`; подключение агента остаётся agent-05.
Реестр `agent/actions.py` исполняет создание, список, поиск и справку.
`SearchRecords` пока вызывает поиск по подстроке: каждое слово длиннее двух букв,
фильтры по контракту, отменённые скрыты по умолчанию. Подмена на смысловой поиск —
в `handle_search_records`. Вызовы БД последовательные через `asyncio.to_thread`.

## Клиент LLM и ошибки

`make_client` берёт `base_url`, `api_key`, `model` из `LLMConfig`, затем из
`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`. Пустой адрес означает OpenAI по умолчанию.
Таймаут 15 секунд, один повтор. Модель не вызывается повторно для текста ответа.

`LLMConfigError` даёт ответ о ненастроенном ассистенте, `openai.APIError` —
о временной недоступности, `ActionParseError` — просьбу переформулировать.
Состояние ожидания сохраняется; `ConversationAccessError` передаётся вызывающему API.

### Отложенные кейсы 3.5 и 3.8

По решению пользователя этот этап выполняется без расширения схем инструментов:

- 3.5: `ask_user` не сохраняет известные параметры создания при неизвестном `title`.
  Для «Напомни завтра в 10» → «Позвонить маме» нужен согласованный частичный черновик.
- 3.8: желаемое поведение — спрашивать день, сохраняя время из «Встреча в 14:45».
  Текущий контракт не хранит время отдельно от даты. Поведение «сегодня» пока сохранено;
  требуется отдельное согласование контракта, затем изменение промпта и хранения.

## Источники решений

- [Rasa patterns](https://rasa.com/docs/reference/primitives/patterns/) — отдельные переходы
  отмены, поправки и продолжения прерванного сценария. Здесь применён ограниченный
  контракт проекта: один черновик и одно отвлечение, без стека flows и лишних подтверждений.
- [Home Assistant HassNevermind (ru)](https://github.com/OHF-Voice/intents/blob/aefbd9a/sentences/ru/HassNevermind/default.yaml)
  — точные фразы отказа. «Не надо» и «стоп» добавлены не из источника, а из контракта проекта.
- [LiveKit context_manager._save](https://github.com/Basit-Arif/livekit-booking-system/blob/93e6e4cf1d8402bf797ec786a5364f5d8e4aa5b6/src/services/context_manager.py)
  — сохранение состояния отдельно от истории и слияние только непустых значений.
  В нашем `merge_pending` дополнительно ограничены поля, которые разрешено дополнять.
