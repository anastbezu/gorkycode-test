# Бенчмарк

Проверка ассистента на наборах кейсов. Наборы — данные в JSON, прогон пишет ответ на каждый кейс в файл, из файла считаются метрики и строится отчёт с графиками.

## Что где

```
eval/
├── datasets/agent/*.json   наборы кейсов агента; формат — cases.py
├── cases.py                формат кейса и загрузка набора с проверкой
├── compare.py              сравнение ответа агента с ожиданием, вердикт по каждому полю
├── harness.py              окружение агента для прогона кейса (база или память, модель или сценарий)
├── run_agent.py            прогон наборов через настоящую модель → results/agent/<метка>.jsonl
├── metrics.py              метрики из файла прогона
├── report.py               отчёт: reports/agent-<метка>/ — report.md, <набор>.md, графики PNG
├── report_pdf.py           тот же отчёт в report.pdf
├── search_cases.py         набор поиска: запросы и цели по шаблонам названий датасета
├── search_eval.py          замер поиска: hit@k, «точно» без ответа, исходы цели изменения
├── results/                файлы прогонов
└── reports/                отчёты
```

Быстрый слой в CI (без модели) лежит в `tests/` и импортирует отсюда: `test_agent_compare.py`, `test_agent_harness.py`, `test_agent_harness_db.py`, `test_eval_cases.py`, `test_eval_metrics.py`.

## Наборы агента
| Файл | Откуда | Кейсов |
|---|---|---|
| `test-cases.json` | таблица `docs/test-cases.md` | 181 |

Новый набор — новый файл в `datasets/agent/`: один набор — одна тема (инструмент или группа подвохов), `id` уникальны внутри файла, «сейчас» и пояс — как у `test-cases.json` (среда 21.10.2026 10:00, Europe/Moscow). Формат и все поля ожидания — в docstring `cases.py`. Набор с ошибкой не загрузится: `test_eval_cases.py` упадёт с номером кейса.

## Прогон агента

Нужны ключ модели в `.env` (`LLM_API_KEY`, `LLM_MODEL`, `LLM_BASE_URL`) и PostgreSQL для кейсов изменений (`TEST_DATABASE_URL`; без базы — `--no-db`, такие кейсы пропускаются с причиной).

```powershell
cd backend
uv run python -m eval.run_agent --label develop-1                 # все наборы, один повтор
uv run python -m eval.run_agent --label develop-1 --runs 3        # три повтора (pass^3)
uv run python -m eval.run_agent --label try --section 2,3         # разделы / категории
uv run --group eval python -m eval.report final                   # отчёт
```

Строка результата пишется сразу после кейса. Прогон прервался — тот же запуск с той же меткой продолжит с места остановки. Модель не ответила 3 кейса подряд (лимит, неверный ключ) — прогон останавливается, такие кейсы не записываются; смените ключ и запустите снова.

## Метрики агента
| Метрика | Что показывает |
|---|---|
| доля пройденных кейсов, по наборам и категориям | кейс пройден, если верны все его реплики |
| pass^k | кейс прошёл во всех k повторах — устойчивость ответа на одну и ту же фразу |
| precision / recall / F1 по инструменту, macro-F1, матрица ошибок | выбор инструмента: что с чем модель путает |
| доля верных по полю | заполнение аргументов: тип, название, даты, цель; неверный инструмент — поля неверны |
| время реплики p50 / p95 | вся реплика: состояние, модель, исполнение, ответ |

Токены на реплику прогон не видит — модельный `usage` до него не доходит.

## Поиск

```powershell
cd backend
uv run python -m eval.search_eval --extended
```

Метрики и группы случаев — в docstring `search_eval.py` и `docs/modules/search.md`.

## Что коммитить
Наборы — всегда. Файлы прогонов и отчёты — только прогоны, на которые ссылается итоговый отчёт: метка в имени файла, коммит и модель — внутри каждой строки.
